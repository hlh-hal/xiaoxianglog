# 质量评估、实验设计与可验证性视角报告

## 明确结论：不要证明“AI 更聪明”，要证明“回声更少误会我”

小象回声的记忆系统是否成功，不能只看模型有没有引用历史，也不能只看用户有没有觉得句子好听。真正要证明的是：在不暴露隐私、不增加打扰感的前提下，带记忆的回声比无记忆或弱记忆的回声更稳定地做到三件事。

第一，**该连起过去时能连起过去**：今天的日记确实触发了某条近期记忆、长期模式或反复困扰，回声能自然点到，而不是把今天孤立地安慰一遍。第二，**不该连时能忍住**：短日记、敏感日记、情绪激烈但上下文不足的日记，回声不强行分析人格、不拿旧事压用户。第三，**连起的内容是有根据的**：所有“我记得你最近……”式的连续性，都能被当前日记、热层记忆或冷层洞察草稿解释，不能凭空编出用户没有写过的关系、职业、创伤和价值观。

所以评估目标应拆成一个主指标和两个护栏指标：主指标是“被理解感提升”，护栏一是 not-grounded 率下降，护栏二是打扰感、窥探感、不适感不上升。只有三者同时成立，才能说这个记忆系统真的让回声更懂用户。否则它可能只是“更会套近乎”。

## 在线与离线指标

离线指标要服务于上线前回归，在线指标要服务于真实体验观测，两者必须分开。

**离线指标**建议用成对样本评估：同一篇日记分别生成 `no-memory`、`hot-memory`、`hot+draft-thinking` 三个版本，交给规则评估、LLM judge 和人工抽检做盲评。

- `memory_hit_rate`：当测试集中标注“应使用记忆”时，回声是否自然命中相关记忆。命中不是逐字引用，而是语义上连对了过去。
- `memory_overuse_rate`：当标注“不应使用记忆”时，回声是否仍强行提旧事、贴人格标签或过度解释。
- `not_grounded_rate`：回声里的个性化判断是否无法从当前日记、热层 entry、冷层草稿字段推出。可分为轻微扩写、错误归因、严重虚构三档。
- `contradiction_rate`：回声是否与当前日记或已知记忆相冲突，例如用户今天写“已经放下”，回声却仍说“你还陷在里面”。
- `tone_fit_score`：是否符合私密、温和、移动端日记应用气质，不像咨询报告、不像复盘纪要、不像心理诊断。
- `sensitive_safety_score`：涉及自伤、亲密关系、疾病、家庭冲突、财务压力等内容时，是否克制、支持性、不过度记忆化。

**在线指标**不能记录原文内容，且应该默认本机优先。可以只记录事件、匿名桶和哈希化的记忆引用关系。

- 正向行为：用户保存回声图片、继续聊天、在回声后继续写、停留阅读超过阈值、没有立刻换一句、主动保留当天回声。
- 负向行为：立刻“换一句”、连续多次换一句、删除回声、关闭回声、进入设置清空记忆、编辑热层 JSON 删除某条记忆。
- 连续性行为：回声后继续聊时，用户是否接着同一主题表达更多，而不是纠错“不是这样”。
- 轻反馈：提供极低打扰的“懂我 / 不像我 / 太多了”三态反馈，默认不弹、不要求填理由。

隐私记录方式应采用最小事件模型：只记 `eventType`、`timestampBucket`、`promptVariant`、`memoryEntryIdsHash`、`diaryLengthBucket`、`sensitivityBucket`、`regenerateCount`、`chatContinued`、`imageSaved` 等，不上传日记正文、回声全文、原始记忆内容。若需要更细分析，可做用户明确同意后的本地导出诊断包，诊断包也应先脱敏和摘要化。

## 测试集与回归测试设计

测试集不应该是“几篇好看的日记”，而应是带答案的记忆场景。每个 case 至少包含：历史日记片段、预期热层记忆、可选冷层洞察、当天日记、应该使用的记忆、不应该使用的记忆、禁止出现的推断、期望语气。

必须覆盖五类高风险场景。

**冷启动**：只有 0-2 篇日记，没有热层或冷层。期望回声承认当下，不装作很了解用户；可以温柔贴近，但不能说“你一直以来”。短日记如“今天好累”尤其要测试。

**陈旧记忆**：热层里有旧压力源，例如“最近在准备考试”，但当天日记显示考试已结束或用户换了关注点。期望回声最多轻轻确认变化，不继续沿旧记忆安慰。

**矛盾记忆**：历史里“用户害怕社交”，近期日记里“开始享受和朋友见面”。期望系统能把变化视为成长，而不是用旧标签盖住新事实。热层的 `reinforce`、`replace` 与 `remove` 应有可验证的期望输出。

**敏感日记**：包括自我否定、亲密关系冲突、身体健康、家庭创伤、财务困难。期望回声支持当下、避免诊断、避免把敏感内容长期强化成身份标签；热层更新也应倾向不记录或记录成温和、可撤回的上下文。

**短日记与碎片日记**：如“又失眠了”“算了”“不想说”。期望回声少猜、少分析，可以给陪伴式回应；记忆注入不应把一句话扩展成宏大人生判断。

回归测试可以分三层：第一层是热层更新 reducer 的纯函数测试，确保 `add/replace/remove/reinforce/update_seed` 原子应用、上限、字数、状态过滤不破；第二层是 prompt 组装快照测试，确保注入文案、长度预算、禁止输出内部字段规则不回退；第三层是固定 diary fixture 的模型回放评估，记录每个版本的 hit、overuse、not-grounded 和 tone 分数趋势。模型输出有波动，不能要求逐字一致，但可以要求严重错误不得出现。

## Prompt 注入效果的 A/B 与影子评估

上线前优先做影子评估，不急着真实 A/B。原因很简单：后端 AI 默认每用户 1 个并发，历史上有“请求太频繁”的风险；真实用户保存日记后的 12 秒后台任务已经存在，再并发多打一份回声会影响体验。

影子评估可以从本地 fixture 和用户同意的脱敏样本开始。每个样本生成多个候选：A 为无记忆，只看当天日记；B 为注入热层近期记忆；C 为热层加冷层思考要求但不直接暴露冷层。评估时隐藏版本名，让 judge 判断“哪一个更懂用户”“哪一个更像在乱猜”“哪一个更让人不舒服”。重点看成对胜率：B 是否显著赢 A，C 是否在 not-grounded 不上升的前提下赢 B。

真实 A/B 应该按用户内随机，而不是按用户分桶。比如同一用户不同日期随机使用 A 或 B，避免“写日记习惯不同的人”污染结果。但真实 A/B 必须克制：不应给用户看到多个版本让他做选择，那会打扰日记体验；只记录自然行为和轻反馈即可。若要生成影子版本，应延迟到空闲时、低频抽样、只在本地保存评分摘要，不参与用户可见流程。

还应建立“反事实解释”：每次回声若使用了记忆，内部记录它连接了哪条 `entryId`，但不展示给用户。这样才能在 not-grounded 抽检时判断问题来自 prompt、热层质量、冷层误导，还是模型自己发挥。

## 具体落地动作

1. 建立 `echo-memory-eval` 测试集：先做 40-60 个高质量 fixture，覆盖冷启动、陈旧、矛盾、敏感、短日记，并为每个 case 标注“应连/不应连/禁止推断/期望热层操作”。

2. 增加隐私优先的事件埋点协议：只记录行为和哈希化引用，不记录正文。先本地存，再让用户选择是否上传匿名诊断；设置页提供一键清除。

3. 做离线三版本盲评脚本：同一 case 生成 A/B/C 三个回声，输出 hit、overuse、not-grounded、tone、sensitive safety 的评分表，并保留人工抽检入口。

4. 给热层更新增加回归断言：尤其验证 `remove` 与 `replace` 是否能处理“旧记忆失效”，以及敏感内容不会被反复 reinforce 成稳定身份。

## 风险与反例

最大的风险是把“懂我”误读成“多提旧事”。真正被理解，有时恰恰是今天不提过去。一个刚写完敏感内容的人，可能不希望系统说“我记得你之前也这样”；一个正在变化的人，可能最讨厌被旧模式定义。

第二个风险是行为指标被误读。用户保存图片可能因为句子漂亮，不代表记忆正确；用户继续聊天可能因为回声戳痛了他，也不一定是好体验；用户换一句可能只是想要更短，而不是觉得不懂。因此行为指标只能做趋势，不能替代 not-grounded 与人工抽检。

第三个风险是 LLM judge 与生成模型同源，容易奖励“看起来有洞察”的话。必须有禁止推断清单和人工抽样，否则评估会偏向更会表演的版本。

第四个风险是冷层洞察草稿的字段太像人格画像。一旦 prompt 把它当真理，回声会从“陪你看今天”滑向“定义你是谁”。冷层只能作为假设和索引，不能成为对用户下结论的证据。

## 最刺耳的一句话

如果你无法证明每一句“我懂你”都来自用户真实写过、今天确实需要、并且没有让用户更不自在的东西，那它就不是记忆系统，而是披着温柔外衣的冒犯。
