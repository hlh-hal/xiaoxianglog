# 产品关系与“被懂得”体验视角报告

## 明确结论：下一版应该克制地做“关系记忆”，不是做“人格档案”

小象回声的下一版记忆系统应继续保留“冷层洞察 + 热层近期记忆”的双层结构，但产品取舍要更明确：冷层负责形成长期理解的假设，热层负责支撑当下回复里的连续感；冷层不直接注入回声，热层也不能变成事实堆栈。真正要建设的是一种“关系记忆”：小象知道用户最近在反复面对什么、哪些事不能轻描淡写、用户更吃哪种陪伴方式、哪些开放问题还没有结束。

因此，下一版不应追求“记得更多”，而应追求“记得刚好、用得更轻”。用户觉得小象懂我，不是因为它展示了多少记忆，而是因为它在今天这篇日记里把过去放在了合适的位置：不抢走今天、不解释机制、不贴标签、不替用户下结论，却能让用户感觉“它还记得我正在走过的那条路”。

## “用户觉得懂我”的可设计信号

“懂我”不是泛泛的情绪价值，可以拆成六个可设计的体验信号。

第一是具体性。回复里要抓住今天日记中一个真实细节，而不是复述“你很不容易”。被懂得的第一感是“它看见了我刚刚写下的那个点”。

第二是连续性。小象可以轻轻连到过去的未完成主题，例如反复出现的关系压力、职业犹豫、身体疲惫、自我责备、最近的小进步。但连续性必须像熟人的记挂，而不是像系统检索结果。

第三是分寸感。最好的记忆使用常常是语气变化，而不是显性引用。比如用户连续几天写“很累”，小象不一定要说“你连续几天都很累”，而可以少一点建议、多一点停靠。

第四是变化感。懂我不只是记住我的痛点，也要看见我变了。用户从“撑不住”到“今天稍微做了一点”，小象要能捕捉这种微小转向，而不是永远用旧标签回复。

第五是主体感。回声不能替用户定义人生，也不能把洞察包装成诊断。它应使用“也许、像是、我听见的是”这类低侵入表达，把解释权留给用户。

第六是隐私安全感。用户要感觉这些记忆只是在这本日记里陪伴自己，而不是被一个后台人格画像系统盯着。越私密的产品，越不能让“智能”表现得像窥探。

## 对冷层 / 热层当前设计的判断

当前冷层 InsightDraft 的方向是对的：本机 IndexedDB、不进后端同步、不进导出、不进聊天历史，符合小象日志的信任基线。它适合承担“长期模式索引”，尤其适合帮助热层判断哪些主题值得保留、哪些变化值得更新。

但冷层的结构现在有一个产品风险：identity、selfPerception、coreValues、lifeStage 这类字段很容易把“暂时的表达”沉淀成“稳定的人格判断”。日记里的用户常常是在情绪峰值里写作，今天说“我就是很差劲”并不意味着这是自我认知事实。下一版冷层应把这些字段从“画像字段”改成“假设字段”，并记录置信度、反例和最近变化。冷层不是小象对用户的定论，而是小象提醒自己“这里要小心”的便签。

热层 EchoHotMemory 的设计非常接近产品所需：10 条上限、150 字约束、原子操作、前端校验、避免全量覆盖，这些都在防止记忆膨胀和 AI 误伤。它适合成为回声里的“近期关系上下文”。

但热层目前如果只存 content，会面临三个问题：一是容易混合事实、情绪和建议偏好；二是旧记忆可能持续强化，造成用户被旧状态困住；三是注入时缺少“可不可说、该怎么说”的使用边界。热层下一版应从“记忆条目”升级为“回复线索”，每条不只写内容，还要知道它适合怎样影响回复。

## 提示词注入：让记忆自然流露，而不是露出系统在调用记忆

提示词注入的核心原则是：当前日记永远是主角，记忆只改变回声的关注点、语气和一两处轻微连接。不要让模型觉得任务是“把记忆用出来”，而要让它觉得任务是“在理解今天时，如果过去自然相关，就带着那份熟悉感回应”。

注入文案可以从“近期记忆列表”改成“你对这个人的轻量关系线索”。每条线索应标注使用方式，例如：可轻轻呼应、仅影响语气、避免直接提及、已经过期需谨慎、需要看见进展。这样模型不会把所有记忆都当作可见素材。

可见回复里应避免三类露馅表达：第一，“我记得你之前……”这种客服式连续性，除非用户自己提到了过去；第二，“这说明你是一个……”这种画像式总结；第三，“结合你的长期模式……”这种分析报告口吻。更自然的方式是把记忆溶进句子的重心里：用户今天又写到同一个挣扎时，小象可以说“这件事好像不是今天才开始消耗你”；用户出现小进展时，小象可以说“这一步很小，但它不像是在原地打转”。

内部提示词还应加入一个硬约束：每次最多使用一条热层记忆，且必须能指出它与今天日记的自然连接点。没有连接点就不用。被懂得不是“强行关联”，强行关联会让用户觉得自己被套进了系统预设。

## 具体落地动作

1. 把热层条目从纯 `content` 扩展为“关系线索”结构：增加 `kind`（事实 / 情绪主题 / 未完成问题 / 陪伴偏好 / 成长变化）、`visibility`（可直接提及 / 仅影响语气 / 避免提及）、`freshness` 或过期时间、`counterEvidence`。这样既不显著增加体量，又能让注入更有分寸。

2. 在回声生成前增加“记忆选择”步骤：从 10 条热层中只选 0-2 条候选，最终可见回复最多自然使用 1 条。选择标准不是 reinforceCount 最高，而是“与今天日记具体细节最相关 + 没有隐私冒犯风险 + 能让回复更温柔准确”。

3. 将冷层更新目标改成“长期假设 + 反例 + 变化”三件事。尤其对 identity/selfPerception/coreValues 字段，提示词中禁止写绝对判断，要求写成“可能在某些情境下呈现”。冷层只给热层更新和语气校准提供参考，不作为可见表达来源。

4. 增加一组“被懂得体验”的离线评测样例：同一用户连续 3-5 篇日记，比较无记忆、强显性记忆、轻量关系记忆三种回复。评分维度不是“信息是否完整”，而是具体性、连续性、分寸感、变化感、主体感和隐私安全感。

## 风险与反例

最大风险是“懂我”滑向“定义我”。日记应用里的用户并不是在提交人格测评，而是在一个安全角落里说一会儿真话。系统如果把脆弱时刻长期固化，会伤害关系。

第二个风险是“记忆炫技”。比如用户今天只写了加班很累，回声却提到过去的家庭矛盾、职业焦虑和自我价值感，这种回复即使技术上相关，也会像越界。

第三个风险是“旧记忆压过新用户”。如果一个人曾长期低落，但最近开始恢复，系统仍持续按“低落的人”回应，会让小象从陪伴者变成旧身份的回音壁。

反例也很重要：有些日记根本不需要记忆。今天写一顿饭、一张照片、一段天气，小象只要看见当下就好。强行连到长期模式，会让轻盈的日记被分析感压重。

## 最刺耳的一句话

如果小象必须靠展示“我记得你什么”来证明懂用户，那它其实还没有学会陪伴，只是在把用户的私密日记变成一份会说话的用户画像。
