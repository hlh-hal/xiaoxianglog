## 心情趋势真实日志漏点修复

- 来源：用户提供 `小象日志备份-2026-07-23.md`。端到端复现确认 Markdown 导入、日期解析和最近七天分组均正确，不涉及 AI 生成；漏点发生在本地情绪提取阶段。
- 根因：评分前会清理“开心的事/充实的事”等模板标题，丢失用户主动分类的情绪语义；词典同时未覆盖“心情美丽、欢乐、充实”等保守可识别表达。因此 7 月 23 日和 19 日被误判为无情绪证据，只有含“开心”的 18 日显示。
- 修复：显式 `mood` 和正文明确情绪词仍优先；只有正文没有明确情绪词时，才把有实际内容的“开心/充实/感谢/不好的事”分区作为兜底证据。空分区及“无/暂无/没有”等占位继续返回 `null`，不会把空模板当平静。兼容 HTML、Markdown 标题、编辑器 blocks 和本项目导出的 `- **分区**：正文` 格式，并过滤“今天不焦虑了”等前置否定表达。
- 真实附件结果：17 日、20 日为空模板，继续断线；18 日 `1.5/愉悦`、19 日 `0.8/轻松`、23 日 `1.5/愉悦`，均显示节点。
- Android `Pixel_8_Codex` 用附件等价数据实测节点日期严格为 `2026-07-18 / 19 / 23`，7 个日期可访问性状态正确，页面横向溢出为 0。截图：`tmp/mood-real-backup-android.png`；验证后已恢复模拟器原有 8 条数据。
- 验证通过：专项 `npx tsx tests/profile-mood-trend.test.tsx`、串行 `npm run build`、`npm run lint`、全量 `npm test`、`git diff --check`。注意不要并行运行 build 与 lint：当前 TypeScript 默认扫描 `dist`，Vite 清理产物时会制造短暂的 TS6053 假失败。
- 代码审查：修正了模板标题正则的边界，避免把“充实的事情很多”误当分区标题；未发现需要继续阻塞的高、中、低优先级问题。回滚只需撤销 `src/utils/moodTrend.ts` 与对应测试，无数据迁移或后端清理。
