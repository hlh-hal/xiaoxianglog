## 日记写作时间统计状态机修复

- 来源：用户反馈连续写作体感约 4 分钟，完成卡只显示约 2 分钟；要求 3 分钟内思考计入、长空闲封顶、多次编辑累计、后台/异常退出不无限计时，正常误差控制在 1 分钟内。
- 根因：旧逻辑虽有 180 秒 activity window，但 1.5 秒自动保存会调用暂停并重建计时状态；自动保存之后的思考时间被截断。正文已自动保存后，返回和生命周期 flush 还可能因正文签名未变化而跳过计时落盘；普通 Tiptap blur 也会把工具栏交互误当离开。
- 决策：云端继续只同步单调递增的 `activeWritingSeconds`，不新增 Prisma 字段或片段表。前端新增独立片段状态机，自动保存只读取投影、不关闭片段；真正的完成、退出、隐藏、后台、系统中断和 180 秒空闲超时才关闭片段。
- 异常恢复：新增按账号和日记 ID 隔离的 `WritingTimeCheckpointV1` localStorage 检查点。片段开始立即写，前台每 15 秒刷新；启动时取 IndexedDB 与检查点累计值较大者，不外推关机后的时间，恢复成功后清理并走现有同步。
- 编辑活动：输入、删除、粘贴、IME、撤销/重做、格式/正文更新、图片增删、用户发起的光标移动和文字选择都会刷新活动时间；程序化加载、单纯页面打开、滚动和自动保存不计时。普通 editor blur 不再暂停。
- 完成卡：改为读取保存成功后的 `activeWritingSeconds`，避免使用可能被自动保存重置的临时状态；分钟继续四舍五入且非零至少显示 1 分钟。
- 测试：新增 `npm run test:writing-time`；`npm test`、`npm run lint`、`npm run build`、`npm run test:editor-exit-save`、`npm run verify:daily-echo-writing-time` 均通过。真实浏览器回归确认跨过 1.5 秒自动保存后，4 分钟路径落盘为约 240 秒；启动恢复确认 120 秒日记与 240 秒检查点合并为 240 秒。
- 兼容与回滚：无数据库迁移，旧日记缺失字段按 0 处理，后端较大值合并规则不变。回滚前端代码即可；遗留版本化检查点会被旧版本忽略。
- 剩余人工验收：当前 `adb devices -l` 没有已授权设备，尚未完成 Android 实体设备切后台、锁屏和系统回收后的手工验证。
