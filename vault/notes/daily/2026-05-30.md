## PWA 内联图片预览重大回归二次修复

- 本质错误：全屏预览只是视觉覆盖，打开前没有同步关闭 Tiptap 的 `contenteditable` 和旧焦点，Android/PWA 会把输入法焦点带进预览层。
- 本质错误：预览图源和正文恢复依赖可能滞后的工具条状态，退出预览时没有同时保护 `content`、`images`、scroll 和 unsaved 状态，导致串到上一次图片或回到底部附件图片区。
- 修复：预览入口改为从当前 `NodeSelection` / 当前选中 DOM 图片解析图片节点，打开前立即 `setEditable(false)`、blur 编辑器、关闭工具条，并保存包含正文 HTML、附件数组、src、滚动位置和未保存状态的快照。
- 修复：`ImageViewer` 挂载和指针按下时主动 blur 当前焦点，并增加 `data-testid="image-viewer"`；退出预览时用快照恢复正文和附件状态，避免旧图片和底部附件区冒出。
- 修复：PWA Service Worker 缓存版本从 `xiaoxiang-pwa-v4` 升到 `xiaoxiang-pwa-v5`，避免手机继续使用旧前端缓存。
- 验证：`npm run build` 通过；Puppeteer 移动端烟测确认预览期间 `contenteditable=false`、焦点为 `BODY`、退出后 `before [图片] after` 仍保留，底部非内联图片数量为 0；成功截图位于 `C:\Users\ASUS\AppData\Local\Temp\codex-pwa-inline-preview-fixed.png`。

## PWA 内联图片 base64 膨胀与预览恢复根因修复

- 根因：正文内联图片曾把完整 `data:image/...base64` 写入 Tiptap HTML，导致一次插图就把正文和历史记录膨胀到几十万字符；点击图片、计算默认附件区、预览快照和历史字数都会反复序列化超长 HTML，表现为工具条弹出慢、滑动卡顿、历史记录显示 `<img src="data:image...`、字数异常。
- 修复：新插入内联图片时，编辑器 DOM 使用 `blob:` 对象 URL 显示，并给节点写入稳定 `data-image-key`；保存/历史快照时将正文图片 `src` 规范化为轻量 `diary-image-ref:<key>`，真实图片仍保存在 `images` 附件数组中。
- 修复：加载日记或恢复历史时，根据 `data-image-key` 从 `images` 数组还原图片显示；打开预览时使用当前图片的实际可显示 URL，同时保持编辑器失焦和 `contenteditable=false`，退出预览后恢复原正文快照，不再吞掉上下文字。
- 修复：`stripAllMarkdown` 与历史摘要生成会先移除内联图片标签、`diary-image-ref` 和残留 base64，避免编辑记录继续把图片源码当文字展示或计数。
- 修复：图库缓存改为按条目签名判断，不再只按 entries 数组引用复用旧缓存；图库会忽略正文中的 `diary-image-ref`，继续从 `images` 附件数组展示真实图片。
- 同步注意：本地 `images` 中的 data URL 上传到云端后，会把正文中的 `diary-image-ref` 改写成上传后的远程 URL，避免远端或下次同步后内联图片失效。
