# 2026-06-30 MVP 架构最小重构

## 目标与边界

- 目标：降低“改 A 坏 B”的风险，让日记主链路通过稳定模型、窄接口和失败隔离与 Vault、云同步、月度回声、通知、社区等功能协作。
- 保持 MVP：未新增依赖、未修改 Prisma schema、未改变线上 API 路径；保留 `diaryService` 作为兼容门面，不做微服务、Redux 或全量重写。
- `blocks`、`prompts`、`backgroundId`、Vault 路径和本地 AI 记忆继续作为本地/兼容数据，不进入日记云同步 DTO。

## 关键改动

- 新增 `src/features/diary/model.ts`、`syncContract.ts` 和 `indexedDbDiaryRepository.ts`，把领域模型、云同步字段和常用 IndexedDB 日记读写从大服务中拆出；旧 import 仍由 `diaryService` re-export 兼容。
- 新增 `DiaryPostCommitCoordinator`：日记先完成 IndexedDB/历史提交，再执行可选副作用；同一 entry 串行、Vault 先于云同步，失败进入报告且不破坏本地保存。Vault 结果只合并路径元数据，不回写旧正文/图片快照。
- 后端 `diary.ts` 与 `sync.ts` 共用 `server/src/modules/diary/diaryEntryCodec.ts`；月度回声通过 `diaryChangeProjector.ts` 接收变更并等待投影完成，失败被隔离。同步回归不再在请求结束后输出月度回声外键错误。
- Editor 抽出保存端口、生命周期 autosave Hook、今日回声协调器和社区发布适配器；App 启动/通知轮询移到 `useAppBootstrap`，`App.tsx` 仅保留路由和 Provider。
- 通知开关、好友关系、Editor 偏好统一收口，页面不再直接共享这些 localStorage 字符串键。
- 新增统一 `npm test` 和 `tests/diary-architecture.test.ts`；同步更新编辑器 E2E 的 IndexedDB v7 fixture 和首次启动跳过状态。

## 后续维护规则

- 新增日记云字段时必须同时更新前端 sync contract、服务端 codec/Prisma 写入和架构契约测试。
- 可选功能不得在日记写入方法中直接 `await` 其内部实现；应注册到提交后协调器或后端投影器，并保证失败隔离。
- `diaryService` 仍是兼容门面，后续按实际需求渐进迁移调用方，不为了缩短文件做无关拆分。
