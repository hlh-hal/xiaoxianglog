## 导出图片有序列表编号修复

- 现象：编辑器/导出预览中的有序列表正常，但 `html-to-image` 生成 PNG 后所有编号变成 `0.`。
- 根因：`html-to-image` 会复制 `::before` 样式，却不会保留 CSS counter 的计数上下文，克隆到 SVG `foreignObject` 后 `counter(...)` 统一解析为 0。
- 修复：`renderExportPng()` 渲染前按 `<ol start>`、`<li value>` 和 `reversed` 规则生成临时 `data-export-list-marker`，导出专用 CSS 用 `attr(...)` 渲染实际编号，完成或失败后恢复原 DOM。
- 影响范围：仅 PNG 导出瞬间的有序列表标记；编辑器、预览、无序列表、正文和主题布局不变。
- 验证：`npx tsx src/utils/exportImage.test.ts`（32 passed）、`npm run lint`，并用真实 Chrome + 生产 `renderExportPng()` 导出确认图片显示 `1. / 2. / 3.`，导出后临时属性数量为 0。

- 来源：用户在 Android 编辑页截图中标注红线，希望正文上滑时的顶部裁切边界只比日期时间底部低一点。

- 视觉验证：真实 Chrome 以 `411×808` 移动视口、叶笺图片主题验证，日期时间底边约 `51.1px`、裁切边界 `56px`、首屏正文顶边 `76px`；背景保持单图连续，无横向遮罩拼接线。截图为 `tmp/editor-top-clip-20260715.png`。
