# 2026-06-05 多端同步 push 500

## 背景

用户反馈手机端日记已到 6月4日，电脑端只到 6月2日；电脑控制台显示 `POST /api/sync/push` 500 和“同步失败”。线上只读检查确认云端当前没有 `2026-06-03` / `2026-06-04` 日记，只有 6月2日附近记录，因此主线是手机端未成功推送上云，而不是电脑端单纯没拉取。

## 修复

- `server/src/routes/sync.ts` 将单条 push 改为可恢复处理：重复 id / Prisma `P2002` 会重查并按同用户更新或返回 conflict，不再让整批请求 500。
- 同步写入时规范化 `diaryDate` 为 `YYYY-MM-DD`，`status` 缺省为 `active`，可选字段用 `undefined` 判断，避免未传字段被误清空。
- 可预期坏数据如未上传的 `data:image/` 图片会返回单条 `skipped`，后续有效 entry 继续处理。
- `src/services/diaryService.ts` 为 push 失败增加 batch/size/id 级错误信息；若服务端返回 skipped，则不推进 push 游标，保留重试空间。
- 新增 `tests/sync-push-regression.test.ts`，覆盖并发重复 push 不返回 500、ISO `diaryDate` 归一化、坏图片条目不阻断后续有效条目。
