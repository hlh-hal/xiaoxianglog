# 2026-06-29 Android 富文本选区白块修复

## 结论

- 白块不是 CSS `::selection`、IME 组合态、DOM 层级或水滴手柄图片本身造成的。
- 根因是 Android 主题把 `android:background` 定义在主题全局：Chromium WebView 的 `PopupTouchHandleDrawable` 是裸 `View`，会继承该背景并在透明水滴后绘制矩形。
- 插入手柄与左右选区手柄会分别受到启动主题和普通无 ActionBar 主题影响，因此两处全局背景都需要移除。
- 用户要求保留系统水滴形状；最终没有新增或替换 `textSelectHandle*` drawable。

## 最终改动

- `android/app/src/main/res/values/styles.xml`
  - 从 `AppTheme.NoActionBar` 移除主题级 `android:background`，保留 `android:windowBackground=@color/app_surface`。
  - 从 `AppTheme.NoActionBarLaunch` 移除主题级 `android:background`，把原启动图移到 `android:windowBackground=@drawable/splash`。
- 未改 `src/pages/Editor.tsx`、`src/index.css`、正文左右间距、Tiptap 行为、版本号或发布配置。

## 后续提示

- 不要在 Activity 主题根级重新加入 `android:background`；需要页面/窗口底色时使用 `android:windowBackground`、根 View 或 WebView 背景。
- CSS、PopupWindow 背景覆盖、自定义手柄、透明 WebView和软件渲染均未解决完整问题，不应继续叠加这些补丁。
- 发布前仍需在最初复现问题的真机冷启动检查中文输入、拖动选区、剪切/复制/粘贴和图片主题；本次未发布 APK、未调整版本号。

## 编辑器顶部背景横向切割线修复

- 用户反馈图片主题在日期栏下方出现明显横向分界，且顶部遮住正文的范围超过日期栏本身。
- 根因是顶部遮挡层在约 `76px + safe-area` 的矮容器中再次用 `background-size: cover` 绘制主题图片；它与全屏背景的裁切比例不同，因此边界无法连续。
- `src/pages/Editor.tsx` 已删除重复背景遮挡层和旧顶部 mask；正文滚动区改为从 `64px + safe-area-inset-top` 开始，内部保留 `12px` 顶部间距，使首屏正文仍位于原来的 `76px + safe-area`，滚动后只裁掉日期栏范围内的文字。
- 浏览器移动端验证覆盖叶笺、红树、米白、靛蓝主题，以及编辑、保存后预览、文字选中状态；图片主题均只有一个背景图层，日期栏底部与滚动区顶部重合，无 Vite 错误或控制台错误。
- 验证命令：`npm run lint`、`npm run build`、`npm run android:sync`、`android\gradlew.bat -p android :app:installDebug --console=plain`，均通过。
- Pixel 8 Android 16 模拟器验证：图片背景连续；顶部正文被日期栏边界裁切；原生选区双手柄无白块；复制、粘贴、撤销成功；crash buffer 为空。
