# 08 — 贝佐斯视角：飞轮分析

> "我们不是在和竞争对手赛跑，我们是在和客户的期望赛跑。"

---

## 一、飞轮定义

**核心飞轮：让客户持续写日记**

```
写得越容易 → 写得越多 → 回顾越有价值 → 越想继续写 → 留存越久 → 数据越丰富 → AI越准 → 回顾更有价值 → 写得更多
```

飞轮的唯一转速指标：**日活中实际完成一篇日记的比例**。一切功能要么给飞轮踩油门，要么给飞轮踩刹车。

---

## 二、35个功能逐一判定

### 🟢 飞轮油门（直接加速"写→看→再写"循环）

| 功能 | 一句话定位 | 归类 |
|------|-----------|------|
| **Editor** | 写日记的唯一入口，降低摩擦就是踩油门 | 核心 |
| **Home** | 每次打开看到自己的日记流，强化"我一直在写"的身份认同 | 核心 |
| **DailyEcho** | AI每天帮你回看昨天的自己，把"写了"变成"值了" | 核心 |
| **OnThisDay** | 时间胶囊效应，让你觉得"幸好我写了" | 核心 |
| **MonthlyEcho** | 月度回顾把零散记录变成成长证据，写日记的理由变强 | 核心 |
| **AnnualEcho** | 年度回顾是最强的"坚持写"奖励，也是社交传播素材 | 核心 |
| **AIChat** | 写完有人懂你，日记从"记录"升级为"对话"，粘性翻倍 | 核心 |
| **DailyReminder** | 唯一主动拉你回来写日记的触点，飞轮的外力启动器 | 核心 |
| **InsightDraft** | 降低写作门槛——不知道写什么？AI帮你起个头 | 核心 |
| **Walk** | 边走边说就能写日记，把"没时间"这个最大障碍干掉 | 核心 |

### 🟡 飞轮润滑剂（不直接转，但减少摩擦或增强动力）

| 功能 | 一句话定位 | 归类 |
|------|-----------|------|
| **Gallery** | 照片让日记更立体，降低纯文字的压力 | 核心 |
| **Search** | 写了几百篇后能找回来，日记才不是黑洞 | 核心 |
| **Themes(15+)** | 换个皮肤有新鲜感，但不会让人多写一篇 | 可砍 |
| **Community** | 看到别人也在写，社会认同降低放弃率 | 社交 |
| **Friends** | 互相可见对方的日记动态，制造"不能断"的社交压力 | 社交 |
| **Leaderboard** | 连续打卡排名，用游戏化对抗惰性 | 社交 |
| **PushNotifications** | 提醒的载体，本身无价值，配合DailyReminder才有效 | 基建 |
| **CustomFonts** | 个性化表达，微弱地增加"这是我的日记"的感觉 | 可砍 |
| **EditHistory** | 让你敢大胆写大胆改，降低"写错"的心理负担 | 可砍 |
| **Export/ShareCard** | 把日记变成可分享的卡片，让写日记这件事有社交回报 | 增长 |

### 🔴 飞轮刹车（消耗注意力但不加速循环）

| 功能 | 一句话定位 | 归类 |
|------|-----------|------|
| **Inbox** | 站内信？这是社交产品的功能，不是日记产品的 | 可砍 |
| **PostDetail** | 社区帖子详情页，鼓励你去社交而不是去写日记 | 可砍 |
| **Trash** | 删除日记——飞轮希望你越存越多，删除是反飞轮的 | 基建 |
| **Login** | 进门的门，不能没有，但永远不该被用户感知到 | 基建 |
| **Register** | 注册流程每多一步就多流失一批人，必须极简 | 基建 |
| **ForgotPassword** | 必要的补救，但理想状态是永远没人需要它 | 基建 |
| **Profile** | 个人主页？写日记的人不需要"人设" | 基建 |
| **EditProfile** | 编辑资料花5分钟，这5分钟本该在写日记 | 基建 |
| **Settings** | 设置越多说明产品越不自信，好产品替用户做决定 | 基建 |
| **Help** | 需要帮助文档说明产品不够直觉化 | 基建 |
| **Privacy** | 法律要求，但不该成为用户的心理负担 | 基建 |
| **Terms** | 同上，必要之恶 | 基建 |
| **FirstRunVault** | 首次使用引导，但如果需要"教"用户用，说明产品还不够简单 | 基建 |
| **LocalVault** | 本地加密？对安全敏感的用户有安慰剂作用，但大多数用户不需要这个复杂度 | 可砍 |

## 三、只留10个留哪些

**原则：砍到只剩飞轮最短路径——写→看→再写。**

| # | 功能 | 留的理由 |
|---|------|---------|
| 1 | **Editor** | 写的入口，砍了就没了 |
| 2 | **Home** | 看的入口 |
| 3 | **DailyEcho** | 每天把"写了"变成"值了"的转化器 |
| 4 | **AIChat** | 日记产品和笔记产品的唯一差异点 |
| 5 | **OnThisDay** | 长期留存的最强锚点 |
| 6 | **Walk** | 降低写作门槛的杀手锏 |
| 7 | **Gallery** | 图文并茂降低纯文字压力 |
| 8 | **Search** | 写多了能找回来，日记才不是黑洞 |
| 9 | **MonthlyEcho** | 月度回顾是飞轮中段的加速器 |
| 10 | **DailyReminder** | 飞轮唯一的外力推手 |

**砍掉的25个去哪了：** 基建类（Login/Register/Settings等）必须保留但不计入"功能"——它们是水电煤，不是产品。社交类（Community/Friends/Leaderboard/Inbox/PostDetail）全部砍掉，它们在培养"社交用户"而不是"写日记的用户"。AnnualEcho合并进MonthlyEcho的年终版。其余个性化/辅助类（Themes/CustomFonts/EditHistory/LocalVault）统统砍掉。

---

## 四、最刺耳的一句话

**你们花了30%的工程量在Community、Friends、Inbox、Leaderboard、PostDetail上——这些功能培养的不是"写日记的人"，而是"逛社区的人"。逛社区的人不写日记，写日记的人不逛社区。你们在用一套社交功能，亲手把飞轮的轴心从"写"偷换成了"看"，而用户不缺一个看的地方——他们缺一个坚持写的地方。**
