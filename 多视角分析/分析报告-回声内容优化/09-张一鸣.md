# 09 - 张一鸣视角：回声内容的推荐系统设计

> 身份：字节跳动创始人，算法思维信仰者
> 核心主张：回声不是文学创作，是一个推荐系统问题

---

## 一、当前回声的核心问题：它在做"内容分发"而不是"信息匹配"

看当前回声：

> "在思考的悬崖边，看见了路标"
> "这像极了张小龙打磨聊天体验的克制哲学"
> "认知升级时，必经的寂静前奏"

这段话的问题，用推荐系统的语言说：**它是一个高曝光低点击的标题党内容。**

具体拆解：

| 推荐系统指标 | 当前回声表现 | 问题 |
|---|---|---|
| **精准度（Precision）** | 低 | "悬崖""路标""寂静前奏"——这些意象跟用户此刻的状态无关，用户没有在悬崖边，他在做产品分析 |
| **召回率（Recall）** | 低 | 用户日记里最核心的信号——"20%差异化优势"+"80%精力集中"——完全没有被召回 |
| **时效性（Freshness）** | 中 | 引用张小龙，但用户此刻需要的不是历史人物类比，是当下可执行的判断 |
| **用户意图匹配** | 差 | 用户在做「战略聚焦」的思考，回声却在给「情绪安慰」，意图错位 |

**一句话诊断：回声模型的特征工程做错了——它提取的是情绪特征（"清醒""可贵""阵痛"），但用户此刻需要的是认知特征（"聚焦""取舍""优先级"）。**

## 二、回声的生成逻辑应该怎么设计？

### 2.1 把日记当做一个「用户query」，回声是「搜索结果」

推荐系统的本质是：**给定用户当前状态（query），返回最相关的结果（echo）。**

所以回声的生成应该分三步：

```
Step 1: 意图识别（Intent Classification）
Step 2: 特征提取（Feature Extraction）
Step 3: 内容匹配与生成（Content Matching & Generation）
```

#### Step 1: 意图识别——用户此刻在干什么？

用户的日记信号：
- "使用多视角分析skill" → 正在做分析工作
- "20+页面不是功能完整，是方向缺失" → 正在做产品诊断
- "找到20%差异化优势，80%精力集中做" → 正在做战略聚焦

意图标签：`产品思考` / `战略决策` / `自我复盘`

**当前回声的错误：它把意图识别成了`情绪疗愈`。**

#### Step 2: 特征提取——哪些信号最重要？

用信息增益（Information Gain）的思路：

| 特征 | 信息增益 | 说明 |
|---|---|---|
| "20+页面 = 方向缺失" | **高** | 这是用户的核心洞察，是认知突破点 |
| "20%差异化 + 80%精力" | **高** | 这是用户得出的行动策略 |
| "对大佬的想法可以再进一步分析" | **中** | 这是改进方向，说明用户在反思决策方法 |
| "不要贪多" | **中** | 这是自省信号 |
| "多视角分析" | **低** | 这是工具/方法，不是洞察本身 |

当前回声提取了什么？"清醒""可贵""克制哲学""阵痛"——这些全是**低信息增益的情绪词**，不是用户日记的特征。

#### Step 3: 内容匹配——回声应该长什么样？

好的回声应该像一条精准的推荐结果：**让用户觉得"这个系统真的理解我在想什么"。**

匹配逻辑：

```
if 用户意图 == "产品战略思考":
    回声应该 = 找到用户思考的「盲点」或「下一步」
    而不是 = 夸用户清醒、给情绪价值

if 用户提到了"20% + 80%":
    回声应该 = 追问"你确定这20%是用户感知到的差异化，还是你自己认为的？"
    而不是 = 说"这像极了张小龙"
```

## 三、改写范例

### 当前回声（问题版）

> **标题：** 在思考的悬崖边，看见了路标
>
> 你说"20+页面不是功能完整，而是方向缺失"……这种清醒非常可贵……这像极了张小龙打磨聊天体验的克制哲学……接纳这种"经历的少"带来的阵痛，它正是认知升级时，必经的寂静前奏。

### 改写回声（推荐系统版）

> **标题：** 你砍掉了80%，但20%是什么还没说
>
> 你说"20+页面是方向缺失"，然后得出"找20%差异化，80%精力集中"——这个判断框架是对的。
>
> 但有个问题：你的日记里只说了"不要做什么"（砍页面），没说"要做什么"（那20%到底是什么）。
>
> 这是两个完全不同的问题。很多产品团队砍完功能之后，剩下的也不是差异化，只是"剩下的"。
>
> **下一步建议：** 用一句话回答——"用户打开小象日志，而不是打开备忘录/Notion/Day One，是因为______。"如果填不上来，说明20%还没找到。

### 对比分析

| 维度 | 当前回声 | 改写回声 |
|---|---|---|
| 是否回应了用户的核心内容 | ❌ 只引用了一句话 | ✅ 完整回应了20%+80%的思考 |
| 是否提供了新信息 | ❌ "像张小龙"是旧信息 | ✅ 指出了"砍掉≠找到"的盲点 |
| 是否有可执行性 | ❌ "接纳阵痛"无法执行 | ✅ 给出了一个具体的填空题 |
| 情绪匹配 | ⚠️ 过度安慰 | ✅ 直接、有建设性的质疑 |

## 四、提示词设计原则（算法思维版）

### 原则1：意图优先，情绪后置

```
【错误逻辑】先判断用户情绪（开心/焦虑/迷茫）→ 给情绪回应
【正确逻辑】先判断用户意图（在做什么/想解决什么）→ 给认知回应
```

推荐系统不会因为你心情不好就推搞笑视频——它推的是你「可能会点击」的内容。回声也应该是用户「会觉得有用」的内容，不是用户「会觉得舒服」的内容。

### 原则2：找到日记的「高信息增益」句子，围绕它生成

提示词中应该有一步：**从日记中提取1-2个信息增益最高的句子，回声必须直接回应这些句子。**

当前回声的问题是：它提取了用户的句子，但回应方式是"夸"而不是"推"。就像推荐系统找到了用户兴趣标签，却推了一个不相关的泛化内容。

### 原则3：给「下一步」，不给「总结」

```
【错误】你的思考很清醒，继续保持。  ← 这是「已读回执」，不是洞察
【正确】你说了20%，但20%是什么？     ← 这是「推动下一步」，是真正的洞察
```

好的推荐系统让用户「继续逛」，好的回声让用户「继续想」。

### 原则4：避免「正确的废话」

以下是当前回声中"正确的废话"：

- "这种清醒非常可贵" → 废话，用户不需要你认证他的清醒
- "接纳这种阵痛" → 废话，用户没说自己痛
- "认知升级的寂静前奏" → 废话，这是鸡汤不是洞察

**判断标准：把这句话从回声中删掉，如果用户不会觉得少了什么，那它就是废话。**

### 原则5：回声的「相关性分数」自检

生成回声后，用这个问题自检：

> "如果这条回声是推荐系统推的一条内容，用户会点进去看吗？"

当前回声：标题"在思考的悬崖边，看见了路标"——点击率预估很低，因为用户没有在悬崖边。
改写回声：标题"你砍掉了80%，但20%是什么还没说"——点击率预估高，因为用户确实在想这个问题。

## 五、系统架构建议

```
日记输入
    │
    ▼
┌─────────────┐
│ 意图分类器   │ → 产品思考 / 情绪记录 / 日常流水 / 决策复盘 / ...
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 特征提取器   │ → 高信息增益句子 + 核心概念 + 行动线索
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 策略选择器   │ → 追问盲点 / 指出矛盾 / 给下一步 / 连接历史 / ...
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 回声生成器   │ → 用选中的策略，围绕高信息增益特征生成
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 废话过滤器   │ → 删除不增加信息量的句子
└─────────────┘
```

**关键洞察：当前系统缺少「意图分类」和「废话过滤」两个模块。** 没有意图分类，回声就会在"安慰模式"和"启发模式"之间随机切换。没有废话过滤，回声就会被鸡汤稀释。

---

## 六、最刺耳的一句话

**你现在的回声系统，本质上是一个情绪按摩器——它检测到用户在思考，就赶紧上去说"你好棒"。但用户要的不是按摩，是一面能照出他没看到的东西的镜子。推荐系统从来不夸用户，它只是把用户最可能需要的东西放到他面前——回声应该学会同样的克制。**
