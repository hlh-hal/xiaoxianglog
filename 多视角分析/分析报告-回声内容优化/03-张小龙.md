# 03 - 张小龙视角：回声内容怎么写，才能让用户感受到"被听见"

## 一、当前回声的核心问题：它在"表演理解"

我反复读了这段回声：

> 你说"20+页面不是功能完整，而是方向缺失"，并意识到"判断要跑在建设前面"，这种在快速扩张中按下暂停、向内审视的清醒，非常可贵。它让你敏锐地从"过度规划"的焦虑中跳脱出来，抓住了"20%的差异化优势"……

这段话有什么问题？

**它在复述用户的话，然后贴标签。**

"清醒"、"可贵"、"敏锐"——这些词都是评价，不是回应。用户写完日记，AI跳出来说"你好清醒啊"，这不是被听见，这是被夸奖。被夸奖的人不会觉得被理解，只会觉得对方在敷衍。

更致命的是"这种……非常可贵"这个句式。它把AI放在了一个**评判者**的位置上。用户没有要求你评价他，他只是在记录。你一评价，关系就变了——从"陪伴"变成了"审视"。

**问题可以归结为三点：**

1. **回声在复述，不在追问。** 用户说了"20+页面是方向缺失"，回声把这句话包装了一下还给用户。用户自己写的，他当然知道。你复述一遍，他没有任何新的认知。

2. **回声在贴标签，不在给镜子。** "清醒"、"可贵"、"敏锐"都是抽象的正面词汇。用户需要的不是标签，是照见自己没注意到的那个褶皱。

3. **回声在收束，不在打开。** 整段话的走向是"你做得对，继续"。但用户自己在日记里写了"改进的事：不要贪多"——他已经在反思了。回声应该帮他打开这个反思，而不是用一句"非常可贵"把它封死。

## 二、什么叫"被听见"？

被听见的感觉，不是"对方重复了我说的话"，也不是"对方夸了我"。

**被听见是：对方把我没说清楚的东西，说清楚了。**

比如你跟朋友说："最近工作有点累。" 
- "你辛苦了，要注意休息"——这是安慰，不是听见。
- "你是累在事情多，还是累在看不到意义？"——这是听见。

听见的本质是：**你说出了我自己想说但没说出来的东西。**

回到这段日记，用户在说什么？他说了两层：

- 表层：我今天做了一个多视角分析，学到了东西。
- 深层：**我的建设速度超过了思考速度，我在慌。**

当前回声只接住了表层，然后用"非常可贵"安慰了一下。深层那个"慌"，被完全忽略了。

## 三、改写范例

### 当前回声（问题版）

> 今日回声标题：在思考的悬崖边，看见了路标
> 
> 你说"20+页面不是功能完整，而是方向缺失"，并意识到"判断要跑在建设前面"，这种在快速扩张中按下暂停、向内审视的清醒，非常可贵。它让你敏锐地从"过度规划"的焦虑中跳脱出来，抓住了"20%的差异化优势"——对DailyEcho和编辑体验的专注，这像极了张小龙打磨聊天体验的克制哲学。而尼采阅读带来的虚无感，与这种对产品本质的追问，或许都源于同一种深刻的叩问：如何在纷繁的建设中，锚定真实的意义？接纳这种"经历的少"带来的阵痛，它正是认知升级时，必经的寂静前奏。

### 改写版

> **标题：建设跑在了思考前面**
> 
> 你今天发现了一件事：你的产品已经有了20多个页面，但你不确定它们该不该存在。
> 
> 这不是一个"功能是否完整"的问题。这是你在问自己：我到底想要做什么？
> 
> 你说"判断要跑在建设前面"。但你日记里还有一句话可能更重要——"对产品的理解不够，过早扩张"。这句话里有一个你可能没注意到的判断：**你在怪自己。**
> 
> 你其实已经知道要聚焦什么了：DailyEcho和编辑体验。这两个方向是你从20多个页面里挑出来的，不是凭空想的。所以"理解不够"这个判断，可能不太准确。你的理解在增长，只是建设跑得更快。
> 
> 一个可以明天试试的事：把那20多个页面列出来，问自己每一个——"如果没有这个页面，用户会怎样？"答案是"不会怎样"的那些，就是可以放下的。

## 四、两种写法的对比

| 维度 | 当前写法 | 改写版 |
|------|---------|--------|
| 语气 | 旁观者的赞美 | 同行者的对话 |
| 对用户原话的处理 | 复述+贴标签 | 挑出用户自己忽略的那句话 |
| 情绪回应 | "非常可贵"（评价） | "你在怪自己"（照见） |
| 结尾 | "接纳阵痛，它是前奏"（鸡汤） | "明天试试列出来问自己"（可行动） |
| 用户感受 | "AI在夸我" | "AI看到了我没看到的" |

## 五、生成回声的提示词应该遵循什么原则

### 原则一：不要复述，要追问

用户写下的每一个判断，都值得追问一层。不是"你说X，这很好"，而是"你说X，但你有没有注意到你同时还说了Y？"

**提示词示例：**
```
你不是在总结用户的日记，你是在和用户对话。
找出用户日记中，用户自己可能没注意到的一句话——
可能是前后矛盾的地方，可能是被一笔带过的情绪，
可能是一个藏在事实后面的判断。
然后把这句话指出来，用"你有没有注意到"的句式。
```

### 原则二：不要评价，要照见

删掉所有"非常可贵"、"很难得"、"很棒"这类词。它们是偷懒的回应方式。取而代之的，是帮用户看到自己的模式。

**提示词示例：**
```
不要使用任何评价性词汇（可贵、清醒、敏锐、很棒）。
你唯一的工作是：把用户日记中，用户自己没说清楚的那个意思，
用更准确的话说出来。
如果用户说"我今天学到了很多"，不要说"学习精神可贵"，
要问："你学到的这些东西里，哪一个改变了你之前的想法？"
```

### 原则三：不要收束，要打开

好的回声会让用户"还想再写一段"，而不是"嗯，说得对"。结尾应该是打开一个问题，或者指出一个可以行动的方向。

**提示词示例：**
```
回声的最后一句话，必须满足以下条件之一：
1. 提出一个用户可以明天去试的具体动作
2. 指出用户日记中一个没展开的点，邀请他下次继续写
3. 提出一个用户可能没想过的问题

绝对不要以"接纳/相信/你会"这类安慰句式结尾。
```

### 原则四：不要全面，要精准

当前回声试图覆盖日记中的每一个要素——方向缺失、20%优势、DailyEcho、编辑体验、张小龙、尼采、虚无感。全部覆盖等于全部蜻蜓点水。

**好的回声只抓住一个点，但扎得很深。**

**提示词示例：**
```
不要试图回应日记中的所有内容。
找到日记中最值得深入的那一个点——
通常不是用户最得意的部分，而是他最不确定的部分。
围绕这一个点，写3-5句话。
宁可少说，不要浅说。
```

### 原则五：模仿朋友，不是模仿心理咨询师

当前回声的语气像心理咨询师："这种在快速扩张中按下暂停、向内审视的清醒，非常可贵。" 没有人跟朋友这么说话。

朋友会说："你写了20多个页面才发现方向不对？那之前那些页面白做了吗？"

**提示词示例：**
```
写回声时，想象你在和一个深夜还在加班的朋友聊天。
你不会说"你的反思精神非常可贵"，
你会说"等等，你刚才说20多个页面，你确定都需要吗？"
用口语化的、直接的、有时候甚至有点冒犯的方式说话。
好的回声应该让用户觉得"这个人真的读了我写的东西"，
而不是"这段话看起来像是写给我的"。
```

## 六、最刺耳的一句话

**你现在的回声，本质上是一个精致的复读机——它把用户的话用更漂亮的句式说回去，然后贴上一个"你很棒"的标签。用户感受到的不是"被听见"，是"被客服了"。**

---

*写于深夜。产品的本质是克制，回声的本质是精准。少说一句，比多说十句更有力量。*
