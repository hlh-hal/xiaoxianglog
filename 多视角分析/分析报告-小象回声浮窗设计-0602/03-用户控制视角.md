# 03-用户控制视角：客户至上的小象回声浮窗设计分析

## 一句话结论

小象回声可以变成一只可爱小象浮窗，但它必须首先是“用户可完全控制的安静陪伴”，其次才是“哇”的情感惊喜。对日记应用来说，真正的客户至上不是让小象更活泼，而是让用户永远感觉：我的日记、我的节奏、我的隐私、我的屏幕，仍然由我掌控。

从贝佐斯的客户至上和逆向工作法看，这个想法应该倒着问：用户保存一篇私密日记后，最希望发生什么？

不是“出现一个很可爱的东西”。

而是：

- 我刚刚写完的情绪被温柔接住。
- 我不担心内容被暴露、被误读、被上传、被别人看到。
- 我想看回应时它在，我不想看时它消失。
- 它不会挡住我继续写、编辑、回看、删除或退出。
- 这个小象长期存在后，仍然让我觉得安心，而不是烦。

所以最优方向不是“常驻宠物浮窗”，而是“保存后短暂出现、可展开、可收起、可关闭、可长期禁用的回声小象”。

## 逆向工作法：先写一条面向用户的发布说明

如果这件事值得做，它的发布说明应该能这样写：

> 保存日记后，小象会在页面角落轻轻出现，用一句温柔的回声回应你。它不会遮挡正文，不会自动朗读，不会默认保存到公开位置，也不会在你写作时打扰你。你可以点开、收起、拖动、关闭，或在设置里彻底关闭小象回声。喜欢的一次回应，可以一键保存为图片或附回这篇日记。

如果产品最后做出来不能兑现这段话，就说明它不是客户至上的设计，而是团队爱上了自己的创意。

## 用户真正害怕什么

### 1. 害怕“写日记时被打断”

日记不是信息流，也不是游戏。用户写完一段话，常常还处在情绪的尾声里。一个活泼小象如果弹跳、闪烁、晃动、说太多话，会把用户从自我表达拉回到“产品在表演”。

客户至上的判断是：小象不能抢用户日记的主角位置。它只能在保存完成后，以低动势、低音量、低面积出现。

建议：

- 写作过程中不出现浮窗，只在保存成功后出现。
- 动画控制在 600-900ms 内，使用轻微探头、眨眼、呼吸，不做跳跃、摇晃、烟花。
- 默认只露出小象头像或半身，不直接展开大段文字。
- 用户继续输入、滚动正文、打开键盘时，浮窗自动退到边缘小图标状态。

### 2. 害怕“我的隐私被产品看见了”

小象回声天然会让用户联想到 AI 读了我的日记。可爱形象会放大亲密感，也会放大隐私焦虑。越像“活物”，越要清楚告诉用户边界。

建议把隐私承诺设计进交互，而不是写成长篇说明：

- 首次开启时用一句短说明：“小象只在你保存后生成回声，你可以随时关闭。”
- 如果回声需要联网或 AI 处理，必须在设置里明确标识“生成方式”和“是否发送内容”。
- 未登录、本地模式、AI 不可用时，也要有本地温柔反馈，不要让用户觉得“保存失败”或“数据丢了”。
- 不做默认语音播报，不做桌面悬浮球式常驻，不做锁屏/通知预览展示日记内容。

隐私设计的原则是：小象越可爱，边界越要清楚。

### 3. 害怕“我关不掉它”

浮窗类功能最大的长期风险不是第一天不喜欢，而是第七天还在挡路。用户对可爱功能的宽容期很短；一旦它像广告、像游戏助手、像客服挂件，就会伤害日记应用的信任感。

必须提供三层控制权：

- 当次关闭：浮窗右上角或长按菜单可关闭本次回声。
- 场景关闭：在编辑页关闭“保存后显示小象回声”。
- 全局关闭：设置页提供“小象回声”总开关，并允许选择显示方式。

推荐设置项：

- 小象回声：开启/关闭。
- 显示方式：角落小象、底部回声卡、仅保存成功提示。
- 自动展开：关闭为默认，用户点按后展开。
- 保存到日记：手动保存，不能默认写回正文。
- 保存到图库：每次手动确认，不能默认保存到相册。

## UI 位置与形式方案

### 推荐方案：右下角“贴边小象”，保存后短暂出现

最适合移动端日记场景的位置是右下角贴边，但要避开底部工具栏、安全区、保存按钮和键盘区域。

表现方式：

- 保存成功后，小象从右下角轻轻探出。
- 默认占屏宽约 56-72px，高度不超过 80px。
- 背景使用纸张感浅底，边缘可有极淡绿色描边或阴影。
- 小象颜色温和，局部使用主色 `#446733`，不要做高饱和 IP 玩偶感。
- 小象旁只出现一条极短气泡，例如“我听见了。”、“今天也被你认真记录了。”，2-3 秒后收起。
- 点击小象后展开回声卡，卡片宽度约屏幕 86%-92%，从底部轻浮层或右下气泡展开。

为什么不是居中弹窗？

因为居中弹窗意味着“产品要求你处理我”。日记保存后，用户最需要的是完成感和自由离开。居中弹窗会把回声变成任务。

为什么不是顶部通知？

顶部离正文和拇指操作区都远，情感感知弱，也容易像系统 toast。小象是陪伴，不是系统日志。

为什么不是常驻悬浮球？

常驻意味着持续占用注意力。日记应用的长期不变需求是安静、私密、可读写，不是宠物养成。

### 备选方案 A：底部“回声抽屉”

如果担心浮窗破坏安静感，可以保留小象形象，但让它只作为底部回声抽屉的入口。

形式：

- 保存后底部出现一条低高度提示条。
- 左侧是小象头像，右侧是一句回声摘要。
- 向上轻拉或点击展开完整回声。
- 适合更保守、更偏工具感的版本。

优势是干扰小、符合现有保存后回声卡逻辑；缺点是“哇”的情绪弱一些。

### 备选方案 B：日记底部“落款小象”

把小象作为这篇日记的温柔落款，而不是全局浮窗。

形式：

- 保存后在日记底部出现一只坐着的小象和一句回声。
- 用户回看这篇日记时可再次看到。
- 可以一键收藏这次回声。

优势是和日记内容绑定最自然；缺点是即时惊喜较弱，也不够“浮窗设计”。

### 不建议方案：全局宠物助手

不建议做成类似桌面宠物的常驻小象，原因很直接：

- 它会让小象日志从安静日记变成陪伴玩具。
- 它会在长期使用中制造视觉疲劳。
- 它会增加误触、遮挡、性能和隐私解释成本。
- 它会把“写日记”这个核心动作变轻。

客户至上不是把用户逗开心一次，而是让用户愿意放心写很多年。

## 权限、开关与控制权设计

### 首次体验

首次触发不要弹复杂权限说明。建议使用轻量底部 Sheet：

标题：开启小象回声

正文：保存日记后，小象会用一句温柔回声回应你。你可以随时关闭，也可以只保留普通保存提示。

按钮：

- 开启
- 仅使用保存提示

底部小字：回声内容仅用于当前回应；是否联网生成应按真实技术方案准确说明。

### 设置入口

建议在“设置 - 写作体验”或“设置 - 小象回声”中提供：

- 小象回声总开关。
- 保存后显示：角落小象 / 底部卡片 / 不显示。
- 回声生成：自动生成 / 点按后生成。
- 回声写回日记：每次询问 / 从不。
- 保存回声图片到图库：每次询问 / 从不。

默认值应保守：

- 小象回声：开启可以，但必须可跳过。
- 自动展开：关闭。
- 写回日记：从不默认写入。
- 保存到图库：从不默认保存。

### 误触防护

浮窗要特别防误触：

- 小象贴边时只响应明显点击，不要覆盖透明大热区。
- 展开卡片后，主要按钮间距要足够，避免“保存到日记”和“关闭”太近。
- 拖动小象时不要触发展开。
- 键盘出现时自动收起，避免挡住输入和工具栏。
- 页面滚动时降低存在感，停止滚动后再恢复。

## 保存到图库与日记的闭环

这个闭环值得做，因为它能把一次情绪惊喜变成长期资产。但必须是用户主动选择。

### 保存到日记

建议按钮文案：`附到这篇日记`

保存位置：

- 不插入正文主内容，避免污染用户原文。
- 放在日记元信息或“回声”独立区域。
- 回看日记时可折叠显示：“小象回声 · 1 条”。

原因：用户写下的是自己的声音，小象回声是回应，不应该伪装成正文的一部分。

### 保存到图库

建议按钮文案：`保存回声图`

图片样式：

- 纸张感背景。
- 顶部显示日期。
- 中间是一句回声。
- 底部小象和“小象日志”轻标识。
- 不默认包含原日记正文，除非用户主动勾选。

首次保存到图库前要说明：

- 将生成一张图片保存到本机图库。
- 默认不包含原文。
- 用户可选择是否包含日期、心情、标签。

这能避免最敏感的问题：用户以为只是保存一句回声，结果图片里带出了私密正文。

### 形成产品飞轮

好的闭环不是为了分享传播，而是为了增强日记习惯：

写日记 -> 保存 -> 收到温柔回声 -> 主动收藏喜欢的回声 -> 回看时重新获得情绪价值 -> 更愿意继续写。

注意，这里的飞轮核心是“更愿意写”，不是“更多分享”。对小象日志来说，分享不是第一目标，信任和复写才是第一目标。

## 长期留存判断

短期看，小象浮窗能制造“哇”。长期看，只有三件事决定它会不会留下：

- 它是否足够少打扰。
- 它是否真的懂保存后的情绪。
- 它是否永远可关闭、可撤回、可不使用。

如果小象每次都出现、每次都展开、每次都讲一大段，它会从惊喜变成噪音。

长期版本应该支持“渐隐式陪伴”：

- 新用户前 3 次保存，表现稍明显，帮助建立情感记忆。
- 熟悉后默认更克制，只露出小象和短句。
- 用户高频忽略或关闭时，自动降低出现频率，并提示可切换为底部卡片。
- 用户主动收藏回声时，再提高该类回声质量和可见性。

客户至上的留存不是把功能强塞给用户，而是观察用户用脚投票后，把产品调到更贴近她的节奏。

## 最小可行方案

建议第一版不要做复杂宠物系统，只做一个可逆的双向门实验：

1. 保存成功后，右下角出现小象头像和一句短回声。
2. 3 秒后自动收起为贴边小象，或用户点击关闭。
3. 点击小象展开回声卡。
4. 卡片提供三个动作：`附到这篇日记`、`保存回声图`、`不再显示`。
5. 设置页提供“小象回声”总开关和显示方式选择。

这件事是双向门，不需要过度犹豫；但隐私默认、保存默认、关闭能力是单向门级别的信任问题，必须谨慎。

## 设计红线

- 不要在用户写作中途弹出。
- 不要默认常驻。
- 不要默认展开长文本。
- 不要默认保存到日记正文。
- 不要默认保存到图库。
- 不要默认包含原文生成分享图。
- 不要让关闭入口藏得很深。
- 不要把小象做成高频任务入口、活动入口、营销入口。

## 最终建议

我建议采用“右下角贴边小象 + 点按展开回声卡 + 强控制权设置”的方案。

视觉上，小象要像纸页边缘探出来的温柔陪伴，而不是屏幕上的客服挂件。交互上，它要把主动权交给用户：保存后轻轻出现，用户愿意就点开，不愿意就自动退场。产品闭环上，把喜欢的回声保存为“日记附属回声”或“本地回声图”，但不污染正文、不暴露隐私、不替用户做决定。

这才符合小象日志的长期不变需求：私密、安静、好写、好读、少打扰。

## 最刺耳但必要的话

如果用户为了躲开小象而少写一句日记，那么这只小象再可爱，也是产品在背叛自己的核心价值。
