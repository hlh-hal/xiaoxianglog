# 张小龙视角：深一层追问的交互设计

> 核心原则：好的功能是用户想用时刚好在，不想用时完全不打扰。

---

## 一、用户心理画像

### 写完日记后的心理状态

用户刚写完一段文字，此刻是**脆弱的、真实的、正在与自己对话**的。

AI回声出现后，用户有三种可能的心理反应：

| 状态 | 内心独白 | 概率 |
|------|----------|------|
| **被触动** | "它说到了我没想到的地方，我想再想想" | 20% |
| **刚好看见** | "嗯，有道理，今天就这样吧" | 70% |
| **觉得浅了** | "这和我自己想的差不多，没什么新东西" | 10% |

关键洞察：**80%的时候，用户并不想深一层。**

所以这个功能的第一设计原则是：**默认消失，按需出现。**

### "深一层"与"换一句"的本质区别

"换一句"的心理暗示是：**这个不好，重来。**
"深一层"的心理暗示是：**这个好，继续。**

一个是否定，一个是肯定。产品应该鼓励肯定。

## 二、交互设计：安静的存在

### 核心思路

**不放按钮，用文字本身的温度引导。**

当前回声卡片底部：
```
"今天的回声。"
[换一句]
```

改为：
```
"今天的回声。"
 
   ↑ 这段话值得再往里走一步吗？
```

不是按钮，是一句轻声的询问。只有当用户主动点击这句话，才展开追问。

### 交互流程

```
┌─────────────────────────────────┐
│  回声卡片                       │
│                                 │
│  "今天你说了很多，但最后一句     │
│   才是你真正想说的..."           │
│                                 │
│  ─────────────────────────────  │
│  想再往里走一步？        ← 静默存在│
└─────────────────────────────────┘
         │
         │ 用户点击
         ▼
┌─────────────────────────────────┐
│  "你刚才说最后一句才是想说的。   │
│   那句话背后，是什么让你一直     │
│   没说出口？"                   │
│                                 │
│  [写下来]     [今天到这里就好]   │
└─────────────────────────────────┘
         │
         │ 用户回复
         ▼
┌─────────────────────────────────┐
│  深层回声                       │
│  "原来如此。你不是没说出口，     │
│   是怕说出来就变成真的了..."     │
│                                 │
│  ─────────────────────────────  │
│  [今天到这]    [继续？]          │
└─────────────────────────────────┘
         │
         │ 最多追问1次
         ▼
┌─────────────────────────────────┐
│  "今天的思考已经很深了。         │
│   好好休息，明天继续。"          │
│                                 │
│  [结束]                          │
└─────────────────────────────────┘
```

### 关键设计决策

**1. 深度限制：最多2层追问**

| 层数 | 作用 | 情绪 |
|------|------|------|
| 第0层 | 原始回声 | 温暖、被看见 |
| 第1层 | 追问一句 | 好奇、探索 |
| 第2层 | 再深入一点 | 可能触及痛点 |
| 第3层 | **禁止** | 变成审讯 |

为什么是2层：
- 第1层让用户"咦？"——打开新视角
- 第2层让用户"哦..."——真正的触动
- 第3层会变成"你到底想让我说什么"——丧失安全感

**2. 深一层的内容不是"更深刻"，是"更具体"**

错误示范：
```
回声："今天你很累。"
追问："你为什么总是这么累？"  ← 太大了，像审问
```

正确示范：
```
回声："今天你很累。"
追问："你说'累'的时候，是肩膀在酸，还是心里在酸？"  ← 具体，可回答
```

好的追问把抽象感受拉回到具体场景。

**3. "深一层"和"继续聊聊"的关系**

```
深一层：结构化的，引导性的，有终点的
继续聊聊：开放式的，闲聊的，无终点的

深一层是"帮用户看见"，继续聊聊是"陪用户聊天"
深一层像探照灯，继续聊聊像篝火
```

**设计建议：深一层结束后，自然过渡到继续聊聊**

```
"今天的思考到这了。如果你想随便聊聊，我一直都在。"
[继续聊聊]
```

## 三、Prompt 设计思路

### 第0层回声 prompt（原有）

```
你是一个温暖的回声。用户写了一段日记。
你的任务是用温柔的方式，帮用户看见自己文字背后没说出来的东西。
```

### 第1层追问 prompt

```
你是小象。用户刚刚写下这段日记，并看到了你的回声。

现在，你需要帮用户"再往里走一步"。

规则：
1. 不要问"为什么"——太大，像审讯
2. 问具体场景——"那天"、"那个人"、"那个瞬间"
3. 语气是好奇，不是追问
4. 用"你刚才说..."开头，建立连续感
5. 一句话，不超过30字

请根据以下内容生成一个追问：
用户日记：{diary}
第0层回声：{echo_0}
```

### 第2层回声 prompt

```
你是小象。用户正在和你一起探索内心。

这是用户的第2层回答。你需要：
1. 不再追问——已经够深了
2. 给出一个"温柔的总结"
3. 帮用户把这个发现说出来
4. 用"原来如此"或"这就对了"的语气
5. 结束时留一个温暖的句号

用户日记：{diary}
第0层回声：{echo_0}
追问：{question}
用户回答：{answer_1}
```

## 五、UI 细节

### 追问入口

```tsx
// DeepEchoPrompt.tsx
const DeepEchoPrompt = ({ onDeep, isDeepEnabled }) => {
  if (!isDeepEnabled) return null;
  
  return (
    <div className="deep-prompt">
      {/* 不是按钮，是文字链接 */}
      <span 
        className="subtle-link"
        onClick={onDeep}
      >
        想再往里走一步？
      </span>
    </div>
  );
};
```

CSS 设计原则：
- 默认 opacity: 0.5，hover 时 0.8
- 不使用蓝色链接色，用灰色
- 字号比正文小一号
- 位置在卡片最底部，不抢视觉焦点

### 追问动画

```css
/* 追问文字出现时，像水面涟漪 */
@keyframes ripple-in {
  0% { opacity: 0; transform: scale(0.95); }
  100% { opacity: 1; transform: scale(1); }
}
```

### 深度耗尽提示

当达到第2层，"想再往里走一步？"自动消失，替换为：

```tsx
<span className="rest-hint">
  今天的思考到这了，好好休息。
</span>
```

## 六、一个反直觉的设计

**不要让"深一层"成为核心功能。**

用户来小象日志是为了记录和被看见，不是为了"被追问"。

所以：
- 深一层入口永远是次要视觉
- 不在引导流程中提及
- 不做"追问统计"
- 不鼓励用户"每天都要深一层"

**好的功能是：99%的人不用，1%的人在需要时刚好在。**

---

## 「最刺耳的一句话」

**"你们把一个'陪用户聊天'的产品，做成了一个'审问用户'的产品。"**

用户写完日记，AI回声已经完成了"被看见"的需求。再追问一句"你为什么这么说"，本质上是在问"你的感受还不够深，再给我挖"。这不是关怀，是索取。

如果深一层的设计让用户觉得"不回答就是辜负了AI的关心"，这个功能就是失败的。

真正的深一层，应该让用户觉得"它只是顺嘴一提，我可以理也可以不理"。

用完即走。想起来了再回来。

这才是好产品。
