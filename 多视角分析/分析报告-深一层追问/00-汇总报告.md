# 深一层追问功能设计 — 多视角诊断报告

> 分析日期：2026-06-07
> 视角：Dan Sullivan、马斯克、张小龙、MrBeast、芒格、蒂尔、乔布斯、贝佐斯、张一鸣、任正非
> 分析对象：将"换一句"改为"深一层追问"的具体功能设计

---

## 多人共识

### 1. "深一层"不是"更深刻"，是"更具体"（8/10 一致）

最大的误区是把"深一层"理解为"AI说更深刻的话"。实际上，**深层 = 把抽象拉回用户的具体场景。**

> 张小龙："追问不是'更深刻'而是'更具体'——把抽象拉回场景。"
> 张一鸣："每层必须信息增益>0——不能是同一层换说法。"
> MrBeast："第一级共鸣确认，第二级意外角度，第三级温柔直击。"

### 2. 最多2-3层，不要5层（7/10 一致）

AI的第二轮追问就开始编造。深度不是目标，触动才是。

> 马斯克："最多挖一层，AI第二轮就开始编造。"
> 张小龙："最多2层追问。第3层禁止变成审讯。"
> 乔布斯："三层：被看见→看见自己→看见真相。"

### 3. "深一层"和"继续聊聊"是不同功能（7/10 一致）

| 维度 | 深一层 | 继续聊聊 |
|------|--------|---------|
| 方向 | 纵向深挖 | 横向漫游 |
| 结构 | 有终点（2-3层） | 无终点（开放式） |
| 场景 | 在卡片内完成 | 跳转到AI聊天页面 |
| 关系 | 深一层结束后自然过渡到继续聊聊 | 独立存在 |

### 4. 不能让用户觉得"被审问"（6/10 指出）

> 张小龙："你们把一个'陪用户聊天'的产品，做成了一个'审问用户'的产品。"
> 芒格："大多数时候，你只是在帮用户表演深度——而表演者最终会厌倦观众。"
> 贝佐斯："飞轮能不能转，取决于你敢不敢在用户不想聊的时候闭嘴。"

### 5. "深一层"的按钮文案很重要（5/10 指出）

不是"深一层"（学术感），不是"再来一句"（廉价感）。

> MrBeast："第一级按钮'还有呢…'，第二级'你确定？'，第三级'最后一句'"
> 张小龙："不放按钮，用文字引导：'想再往里走一步？'"

## 有意思的分歧：应该有几层？

| 立场 | 代表 | 层数 | 理由 |
|------|------|------|------|
| **1层派** | 马斯克 | 1层 | AI第二轮就开始编造，不如把第一层做到极致 |
| **2层派** | 张小龙、乔布斯 | 2层 | 第1层打开视角，第2层触及真相，够了 |
| **3层派** | MrBeast | 3层 | 共鸣→意外→直击，三层火箭模型 |
| **5层派** | Dan Sullivan、张一鸣 | 5层 | 从事实到本质的完整递进 |

**分析**：层数多少取决于AI能力。当前MiMo模型的深度追问质量还不稳定——**建议从2层起步**，验证质量后再考虑扩展到3层。5层在现阶段会暴露AI的弱点。

## 具体设计方案（综合共识）

### 交互流程

```
[基础回声] 
  ↓ 用户点击"想再往里看看？"
[第1层追问] — 更具体的场景
  ↓ 用户点击"还有呢…"  
[第2层追问] — 触及真相的镜子
  ↓ 自然收束
[继续聊聊入口] — "想继续聊？"
```

### 每层的内容策略

| 层级 | 做什么 | 不做什么 | 字数 |
|------|--------|---------|------|
| 基础回声 | 接住情绪+温和洞察 | 不要名人类比、不要鸡汤 | 50-80字 |
| 第1层 | 引用日记原文中的一个细节，问一个具体的问题 | 不要抽象总结、不要评价 | 30字以内 |
| 第2层 | 把用户的两个不同板块连接起来，指出用户自己没看到的关系 | 不要下结论、不要给建议 | 30字以内 |

### Prompt 设计

**第1层追问 Prompt：**
```
你刚才对用户的日记生成了这段回声：
{基础回声内容}

用户的日记：
{日记原文}

现在，请基于回声中的一个具体点，问用户一个更具体的问题。
这个问题必须：
1. 引用日记里的一个原词或原句
2. 帮用户从抽象思考回到具体场景
3. 不超过30字
4. 用问句收尾
5. 语气：像朋友好奇地追问，不像面试官

只输出追问内容，不要输出"第1层追问"等字段名。
```

**第2层追问 Prompt：**
```
你对用户的了解：
{洞察草稿}

用户的日记：
{日记原文}

第一层回声：
{基础回声}

第一层追问：
{第1层追问内容}

用户可能的回答：（AI推测或留空）

现在，请把日记中两个不同板块的内容连接起来，说出一个用户自己可能没注意到的关系。
不超过30字。
语气：温柔的镜子，不是诊断。
```

### UI 设计

- 基础回声卡片下方，不放按钮
- 用轻柔文字引导："想再往里看看？"（灰色小字，可忽略）
- 点击后，新内容自然生长在卡片底部（动画：从下往上淡入）
- 第2层之后，引导文字变为"继续聊聊？"→跳转AI聊天页面
- 层级之间用微妙的分隔线区分

### 数据结构变化

```typescript
interface DailyEcho {
  status: 'saved' | 'failed' | 'dismissed';
  content: string;           // 基础回声
  // 新增：
  layers?: EchoLayer[];      // 追问层
  styleId: string;
  generatedAt: string;
  sourceEntryUpdatedAt: string;
}

interface EchoLayer {
  content: string;           // 该层内容
  type: 'deeper';            // 类型
  generatedAt: string;
}
```

不需要 `currentDepth` 字段——`layers.length` 就是当前深度。

### 深度限制

- **硬限制：最多2层**（MVP阶段）
- 2层之后自然过渡到"继续聊聊"
- 未来验证质量后可考虑第3层

## 实施优先级（任正非的三阶段）

### Phase 1（第1周）：最小可行版本

**只做三件事：**
1. "换一句"按钮文案改为"想再往里看看？"
2. 新增第1层追问的prompt和API调用
3. 追问内容显示在基础回声下方

**不做：** 第2层、动画、层级指示器、洞察草稿联动

### Phase 2（第2-3周）：打穿核心

4. 第2层追问实现
5. 追问内容存入DailyEcho.layers
6. 2层后自然过渡到"继续聊聊"
7. Prompt质量打磨（投入80%精力）

### Phase 3（第4周+）：体验深化

8. 追问与洞察草稿联动（追问时注入用户画像）
9. 动画和视觉优化
10. 数据埋点：追问点击率、每层完成率
