## 核心判断

用户点击"深一层"，本质是一次**信息增益请求**——当前回声的信息量不够，用户想要更多信号。算法设计的目标不是"更深"，而是**每一层的信息增益最大化**。

---

## 一、递进模型：五层追问的算法设计

把每条日记看作一个信息场，回声是对这个场的采样。"深一层"就是在已有采样基础上，做**更精细的下采样**。

### 信息场分层模型

```
Layer 0（日记原文）    → 用户说了什么（事实层）
Layer 1（初始回声）    → AI看到了什么（共情层）
Layer 2（深一层）      → 这件事可能意味着什么（模式层）
Layer 3（深二层）      → 这个模式背后的需求是什么（需求层）
Layer 4（深三层）      → 用户真正想要的是什么（本质层）
Layer 5（深四层）      → 如果回到明天，用户会怎么做（行动层）
```

### 每层递进规则

| 层级 | 信息类型 | 递进策略 | 输出公式 |
|------|---------|---------|---------|
| L1 | 事实复述 | 镜像用户的话，不加工 | "你今天…" |
| L2 | 模式识别 | 从单次事件中提取可复现的pattern | "这让我想到…" |
| L3 | 需求翻译 | 把情绪翻译成未被满足的需求 | "也许你真正在意的是…" |
| L4 | 本质追问 | 用一个反直觉的角度重新定义问题 | "换个角度看…" |
| L5 | 行动建议 | 给出一个最小可执行的下一步 | "明天你可以…" |

**关键原则：每一层必须比上一层信息增益 > 0。** 如果增益为0，停止追问。

## 二、内容策略：用推荐算法的思路做追问

### 2.1 信息增益公式

```
InfoGain(L_n) = Novelty × Relevance × EmotionalCapacity

Novelty       = 当前层输出与上一层的文本相似度的反函数
Relevance     = 与原始日记主题的语义距离（不能太远）
EmotionalCapacity = 当前时刻用户能接收的情绪强度（安全阀）
```

**如果 InfoGain < 阈值，不再生成下一层，改为展示"你想聊聊什么？"**

### 2.2 内容多样性策略

借鉴推荐系统的探索-利用平衡：

- **L1-L2（利用期）**：高度贴合用户原文，不做跳跃
- **L3（探索期）**：引入一个用户没提过但相关的新视角
- **L4-L5（收敛期）**：回到用户可执行的具体行动

### 2.3 个性化权重

根据用户历史日记数据，动态调整每层侧重：

```python
# 用户画像标签
user_profile = {
    "action_oriented": True,    # → L5行动层权重提升
    "emotional_explorer": True, # → L3需求层权重提升  
    "pattern_seeker": False,    # → L2模式层权重降低
    "depth_tolerance": 3,       # → 最多追问到L3
}
```

## 三、深度限制设计

### 3.1 硬限制：最多5层

不是因为技术限制，而是因为：
- **L5之后信息增益趋近于零**——哲学化追问变成空转
- 用户耐心的半衰期约3次交互
- 超过5层，AI开始"编造洞察"

### 3.2 软限制：自适应停止

```python
def should_continue(current_layer, prev_response, user_engagement):
    info_gain = calc_info_gain(current_layer, prev_response)
    
    # 停止条件
    if info_gain < 0.2:
        return "该聊聊别的了"
    if user_engagement.click_speed < 1.5s:
        return "用户在无脑点"  
    if emotional_intensity > 0.8:
        return "情绪过载，需要缓冲"
    if current_layer >= 5:
        return "到顶了"
    
    return "继续"
```

### 3.3 安全阀机制

- **情绪过载检测**：L3开始检测情绪强度，超过阈值自动降低追问深度
- **重复模式检测**：如果连续两层输出高度相似，强制停止
- **用户疲劳检测**：点击间隔 < 1秒，视为"无脑点"，展示温和退出提示

## 四、Prompt设计

### 4.1 系统Prompt（每层共享）

```
你是小象，一个温暖的回声。用户在写日记，你在帮他看见自己。

规则：
1. 每次回复不超过2句话，80字以内
2. 不要给建议（除非是最后一层）
3. 不要用"你应该"、"你需要"这类指令式表达
4. 每一层必须带来新的信息，不能重复上一层
5. 用具体画面，不用抽象概念
```

### 4.2 分层Prompt模板

**L1 共情层：**
```
用户日记：{diary_text}
请用温暖的语气复述用户经历的事情，加入一个细节观察。
```

**L2 模式层：**
```
用户日记：{diary_text}
上一层回声：{prev_response}
请从用户的经历中识别一个可能反复出现的行为模式或情绪模式。
不要说教，只是轻轻指出来。
```

**L3 需求层：**
```
用户日记：{diary_text}
已有洞察：{layer1_response} → {layer2_response}
请把用户表面的情绪翻译成一个更深层的需求。
用"也许你真正在意的是…"
```

**L4 本质层：**
```
用户日记：{diary_text}
已有洞察链：{all_prev_responses}
请用一个用户可能没想过的角度重新看待这件事。
不要否定之前的洞察，而是增加一个新维度。
```

**L5 行动层：**
```
用户日记：{diary_text}
完整洞察链：{all_prev_responses}
请给出一个用户明天就能做的最小行动。具体、微小、不增加负担。
```

## 五、UI交互设计

### 5.1 视觉递进

每深一层，UI做**视觉下沉**：

- L1：白色背景，正常字号
- L2：背景微微变暖（#FFF8F0），字号略小
- L3：背景更暖（#FFF0E0），加一条左侧暖色竖线
- L4：背景暖橙（#FFE8D0），左侧竖线变粗
- L5：回到白色，但底部出现一个行动卡片

### 5.2 层级指示器

```
◈ ◈ ◈ ○ ○    （当前在第3层，共5层上限）
```

- 填充圆点 = 已展开的层
- 空心圆点 = 可继续的层
- 不显示超过当前深度+1的点（给用户预期但不剧透）

### 5.3 退出设计

- "深一层"按钮始终存在，但到上限时变为"换个话题聊聊"
- 用户滚动到页面顶部时，展示完整洞察链的摘要卡片
- 长按任意一层回声，可以"从这里重新开始"

## 六、与"继续聊聊"的关系

### 6.1 职责边界

| | 深一层 | 继续聊聊 |
|--|--------|---------|
| 方向 | 纵向深挖 | 横向拓展 |
| 目标 | 挖到本质 | 延伸话题 |
| 终点 | 有明确终点（L5） | 无明确终点 |
| 上下文 | 基于洞察链 | 基于完整对话 |

### 6.2 衔接规则

- 深一层结束后，自动出现"继续聊聊"入口
- 深一层的完整洞察链作为"继续聊聊"的上下文种子
- "继续聊聊"中用户如果回到原话题，可以触发新一轮深一层

## 八、冷启动策略

新用户首次使用深一层：
- 默认只开放到L3（不吓到用户）
- 根据前3次使用数据动态调整深度上限
- 前5次使用，每层增加一句引导语："想再深一点吗？"

## 最刺耳的一句话

**你们设计了五层追问，但用户90%的流失会发生在第二层。不是因为第二层做得不好，是因为第一层就没能让他觉得"被看见了"。你花时间优化递进算法，不如花时间把第一层的共情准确率从60%提到90%。地基没打好的楼，层数越多塌得越快。**
