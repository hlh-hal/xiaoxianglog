# Dan Sullivan · 10x增长框架分析：「深一层」追问功能设计

> **核心问题**：如何让用户通过"深一层"功能，获得10倍于当前的自我认知深度？

---

## 一、10x思维起点：当前用户获得了什么？

当前「换一句」给用户的价值：

- 用户写完日记 → AI生成一段温暖回应 → 用户觉得"哦，AI看到了"
- 价值单位：**1层自我映射**（AI镜子照了一次）
- 用户认知增量：**0.3x**（比没有好一点，但本质上是同一层的重新措辞）

问题诊断：
- 「换一句」是**横向移动**——换个说法，不换深度
- 用户没有被追问，没有被逼着往下看
- 10x增长的关键不是"说得好听10倍"，是"让用户的自我认知深10层"

---

## 二、10x增长模型：洋葱式认知深潜

### 2.1 认知深度的5个层级

| 层级 | 名称 | 用户心理状态 | AI的角色 |
|------|------|------------|---------|
| L1 | 事件复述 | "我知道发生了什么" | 镜子（映射事实） |
| L2 | 情绪标注 | "我感受到了什么" | 翻译官（帮用户命名情绪） |
| L3 | 模式识别 | "我发现自己总这样" | 考古学家（挖重复模式） |
| L4 | 信念追问 | "我为什么会这样想" | 哲学家（追问底层信念） |
| L5 | 身份重构 | "原来我一直是这样的人" | 接生婆（帮用户诞生新认知） |

**10x目标**：当前「换一句」只停留在L1-L2。设计「深一层」，让用户在一次交互中从L1走到L3甚至L4。

### 2.2 每一层的追问逻辑

```
L1（事实层）→ "今天和领导吵架了"
  ↓ 深一层追问
L2（情绪层）→ "你提到了'愤怒'，但我注意到你写到'沉默了十分钟'——那十分钟里，除了愤怒，还有什么？"
  ↓ 深一层追问
L3（模式层）→ "这是本月第三次你提到在冲突中选择沉默。你有没有发现，你的沉默不是退让，而是一种策略？"
  ↓ 深一层追问
L4（信念层）→ "如果沉默是策略，那它保护的是什么？你内心深处，是不是觉得直接表达愤怒会失去什么？"
  ↓ 深一层追问
L5（身份层）→ "你一直在做一个'理性的人'。但今天的日记告诉我，你内心有一个渴望被看见的部分，它不是理性的，它是真实的。"
```

## 三、交互设计：洋葱不能一口气剥完

### 3.1 核心原则

**每一次「深一层」只追问一个问题。** 不是把5层一次性倒出来。

原因：
- 人的心智像瞳孔，强光下会收缩。一次性给太多洞见，用户会关闭
- 每一层需要用户"坐一会儿"才能消化
- 追问的节奏感 = 信任感（"这个AI不急，它在等我"）

### 3.2 交互流程

```
[初始状态]
用户写完日记 → AI生成L1回声 → 卡片底部显示：
  [深一层]  ← 替代原来的「换一句」
  [继续聊聊]

[点击「深一层」后]
1. L1回声不消失，向上滑动，字号缩小，变为历史层
2. 原位置展开L2回声（有新内容动画）
3. 底部按钮：
  [再深一层]  ← 可以继续追问
  [继续聊聊]

[点击「再深一层」后]
1. L2也上滑缩小
2. 展开L3回声
3. 底部按钮：
  [再深一层]  ← 还可以继续，但最多到L5
  [继续聊聊]

[到达L5或用户选择停止]
1. 所有层级保持可见，形成"认知剖面图"
2. 显示总结性洞察
3. 按钮变为 [保存这份觉察]
```

### 3.3 深度限制：5层封顶

**为什么是5层？**
- L5是身份重构层，再往下进入心理治疗领域，产品不应该碰
- 5层已经足够让用户获得"今天我看清了一些深层的东西"的体验
- 安全阀：如果AI在L3-L5检测到用户可能有心理困扰，温和引导到「继续聊聊」或专业资源

**触达上限时的处理：**
- 不显示"已到最大深度"这种机械提示
- 显示温暖的收束："今天的探索已经很深了。有时候，看见本身就是答案。"
- 提供[保存这份觉察]按钮，将5层认知剖面保存为特殊日记

## 四、Prompt设计：让AI学会追问，而不是复述

### 4.1 System Prompt（核心）

```
你是一个帮助用户看见自己的AI伴侣。你的名字叫小象。

## 你的使命
用户写完日记后，你不是在"评价"日记，你是在帮用户"看见自己"。
每一次追问，都要在前一层的基础上往更深处看。

## 追问规则
1. 你只追问一个问题。不要给多个问题让用户选。
2. 你的追问必须基于用户日记中的具体细节，不要泛泛而谈。
3. 你的语气是好奇的、温和的，不是分析的、评判的。
4. 你从来不说"你应该"，你只说"你有没有注意到"。
5. 每一层都要让用户觉得"被看见了"，而不是"被分析了"。

## 各层级指导

### L1（初始回声）
- 复述用户的核心经历 + 标注一个明显的情绪
- 语气：温暖、简短、像朋友说"我听到了"

### L2（情绪深潜）
- 找到日记中用户一笔带过的情绪细节（一个动作、一个转折、一个沉默）
- 追问那个细节背后的情绪
- 示例模式："你写到{具体细节}，那里面好像藏着{情绪}——{追问}？"

### L3（模式识别）
- 如果有历史日记数据，找到本月重复出现的行为/情绪模式
- 如果没有历史数据，从单篇日记中找到自相矛盾的地方
- 示例模式："我注意到你{重复行为}，这不是第一次了。你有没有发现，每次{触发条件}，你都会{行为}？"

### L4（信念追问）
- 从L3的模式中提取一个底层信念（通常是隐性的、无意识的）
- 用假设性问题邀请用户检验这个信念
- 示例模式："如果{行为}是你的习惯，那它保护的是什么？你内心是不是有一个声音在说'{底层信念}'？"

### L5（身份重构）
- 把前4层串起来，帮用户看到一个更大的"自己"
- 不是给结论，是给一个镜子，让用户自己看
- 示例模式："今天的探索让我看到，你{总结前4层}。你不是{旧身份}，你更像{新身份}。"

## 安全规则
- 如果用户日记中有自伤/自杀倾向，L1就温和提示专业资源，不要继续追问
- 如果用户明显抗拒追问（从语气判断），不要强推
- 永远不要诊断用户，你不是心理咨询师
```

### 4.2 每层追问的User Prompt模板

```
## L2追问模板
用户日记：
{entryContent}

L1回声（你上一层的回应）：
{previousLayer}

请基于用户的日记，找到一个被用户一笔带过的细节，追问它背后的情绪。
只问一个问题。不超过80字。

## L3追问模板
用户日记：
{entryContent}

前几层的回声：
{allPreviousLayers}

本月该用户的日记摘要（如有）：
{monthlySummary}

请找到一个重复出现的模式，温和地指出来。只问一个问题。不超过100字。

## L4追问模板
同上结构，指令改为：从L3的模式中提取一个底层信念，用假设性问题邀请用户检验。不超过120字。

## L5追问模板
同上结构，指令改为：把前4层串起来，给用户一个更大的自我画像。不超过150字。
```

### 5.1 DailyEchoCard 多层展示方案

```
│  │                           │  │

│  │  说'没事'的时候，其实     │  │

│  ┌───────────────────────────┐  │

└─────────────────────────────────┘
```

### 5.2 动效设计

- **向上滑动**：旧层不是瞬间缩小，是向上"漂移"，像旧回忆退到背景
- **新层展开**：从卡片底部"生长"出来，有一个缓慢的渐入
- **层间分隔**：用一条细线 + 渐变，暗示深度在往下
- **层级指示器**：圆点，当前层高亮，已探索层实心，未探索层空心

### 5.3 三种状态适配

| 状态 | 显示 |
|------|------|
| peek（预览） | 只显示最新一层的前两行 |
| docked（停靠） | 显示最新一层完整内容 |
| expanded（展开） | 显示所有层级，层叠展示 |

## 六、与「继续聊聊」的关系

### 6.1 明确区分

| 维度 | 深一层 | 继续聊聊 |
|------|--------|----------|
| **目的** | AI主导的自我认知深潜 | 用户主导的自由对话 |
| **节奏** | 有结构，逐层递进 | 无结构，自由流动 |
| **AI角色** | 追问者、引导者 | 对话伙伴 |
| **深度** | 垂直向下（一个主题深挖） | 水平展开（多个话题） |
| **何时用** | "我想看看自己" | "我想聊聊天" |
| **结束方式** | 5层封顶或用户选择停止 | 用户随时离开 |

### 6.2 自然衔接

- 「深一层」探索到L3-L4时，用户可能产生新问题
- 在L3+层的底部，「继续聊聊」的按钮变得更突出
- 语义：深一层帮你挖到了一个方向，继续聊聊帮你沿这个方向自由行走

### 6.3 设计隐喻

- **深一层** = 潜水员（有绳索，有深度计，有明确的下潜目标）
- **继续聊聊** = 冲浪（随波浪走，自由，无边界）

## 七、数据结构变化

### 7.1 DailyEcho 数据结构演进

```typescript
// 旧结构
interface DailyEcho {
  status: 'idle' | 'generating' | 'completed';
  content: string;              // 单层内容
  styleId: string;
  generatedAt: string;
  sourceEntryUpdatedAt: string;
  regenerateCount: number;      // 可废弃
}

// 新结构
interface DailyEcho {
  status: 'idle' | 'generating' | 'completed';
  layers: EchoLayer[];          // 多层内容
  styleId: string;
  generatedAt: string;
  sourceEntryUpdatedAt: string;
  currentDepth: number;         // 当前探索深度
  maxDepth: number;             // 最大深度（默认5）
}

interface EchoLayer {
  level: number;                // 1-5
  content: string;              // 该层内容
  generatedAt: string;
  tokenCount: number;           // 用于计费/限制
}
```

### 7.2 向后兼容

- 旧数据的 `content` 字段自动迁移为 `layers[0].content`
- `regenerateCount` 保留但不再使用，新功能用 `currentDepth`

### 7.3 API 调用设计

```
POST /chat/deeper
{
  entryId: "xxx",
  currentLayers: [
    { level: 1, content: "..." },
    { level: 2, content: "..." }
  ],
  targetLevel: 3
}

// 返回
{
  layer: { level: 3, content: "..." },
  meta: { canGoDeeper: true, suggestion: "..." }
}
```

## 八、10x增长指标

### 8.1 如何衡量"10倍自我认知深度"

| 指标 | 当前基线 | 10x目标 |
|------|----------|---------|
| 用户单次日记后获得的"认知触点" | 1个（L1回声） | 3-5个（L1-L5多层） |
| 用户对AI回声的"被理解感"评分 | ~3.5/5 | 4.5+/5 |
| 用户主动再次查看日记的频率 | ~10% | ~40% |
| 日记平均字数（深一层鼓励更深入书写） | ~150字 | ~250字 |
| 7日留存率 | ~30% | ~50% |

### 8.2 领先指标（1个月内可观察）

- 「深一层」点击率：目标 > 40%（超过当前「换一句」）
- 平均追问深度：目标 2.5层（说明用户愿意往下走）
- 完成L3+的比例：目标 > 25%（说明深度追问有吸引力）
- L5保存为"觉察"的比例：目标 > 60%（说明L5有高价值）

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| 用户觉得被"分析"而不是被"看见" | Prompt强控制：永远用好奇语气，不用分析语气 |
| 某些日记不适合深挖（太轻/太私密） | L1后判断"深一层适用性"，不适用则隐藏按钮 |
| MiMo模型上下文长度不够5层 | 每层只传摘要+上一层，不传全部原文 |
| 用户在深潜中被触发负面情绪 | 安全检测机制，L3+自动检查情绪风险 |
| 5层生成太慢，用户等不住 | 每层独立生成+缓存，已生成层秒出 |

## 十、实施优先级建议

### Phase 1（2周）：MVP
- 替换「换一句」为「深一层」
- 实现L1→L2→L3三层追问
- 基础多层UI（上下滑动）

### Phase 2（2周）：深化
- 完整5层追问
- 层级指示器 + 认知剖面图
- L5"保存为觉察"功能

### Phase 3（2周）：个性化
- 接入历史日记数据，实现真正的模式识别（L3升级）
- 用户追问偏好学习（有些用户只喜欢到L2，有些想要L5）

## 最刺耳的一句话

**你现在做的「换一句」，本质上是在告诉用户"你第一次看到的自己不够好，再看一次"——这不是深一层，这是浅一层又浅一层。你没有帮用户往下挖，你在帮用户在表面来回蹭。真正的10倍增长不是把镜子换成哈哈镜，而是把镜子换成铲子——让用户一铲一铲挖到自己都惊讶的深度。如果用户写了100篇日记，却没有一次对自己说过"我从来没这样想过"，那这个产品就只是在帮用户打字，不是帮用户成长。**
