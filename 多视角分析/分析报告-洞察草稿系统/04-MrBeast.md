# 洞察草稿系统设计 —— MrBeast 视角

> **核心原则：** 每一次写日记，都必须让用户觉得"不写亏了"。洞察草稿不是功能，是留存引擎。

---

## 一、第一性原理：用户为什么离不开一个日记App？

MrBeast 做 YouTube 的底层逻辑：**前3秒抓住你，第30秒给你一个"不看完就亏了"的理由，结尾给你一个"必须回来看下一个"的钩子。**

洞察草稿系统必须复刻这个逻辑：

| YouTube 留存逻辑 | 洞察草稿对应 |
|---|---|
| 前3秒 hook | 打开App就看到"你已经连续写了12天，你的成长轨迹正在形成" |
| 中间持续高潮 | 每写完一篇，洞察草稿实时更新，用户亲眼看到AI在"理解"自己 |
| 结尾钩子 | "明天再写一篇，你的人格画像将首次完整" |

**用户不是在写日记，用户是在看一部关于自己的连续剧。洞察草稿就是这部剧的"剧情大纲"——你永远想知道下一集会发生什么。**

## 二、增长飞轮设计

```
写日记 → 洞察草稿更新 → 用户看到"自己在变化" → 想写更多来验证 → 洞察更精准 → 更离不开
     ↑                                                                    ↓
     ←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←
```

这个飞轮的关键节点：

### 2.1 首次写入的"Wow Moment"（Day 1 留存）

用户写完第一篇日记后，**5秒内**必须看到：

```
📝 你的第一篇洞察画像已生成：

🔍 今日主线：你在寻找方向
⚡ 核心矛盾：想行动 vs 怕失败  
🧭 人格特质：内省型思考者
🌱 成长方向：从思考走向行动

💡 这只是起点。写得越多，这个画像越像真正的你。
```

**关键设计：** 第一次的洞察必须足够"准"但又明显"不完整"。让用户觉得"它看到了我一部分，但我想让它看到更多"。这是成瘾的第一口。

### 2.2 连续性奖励（Day 3-7 留存）

**绝对不能让用户觉得"停一天也没关系"。**

- **连续3天写日记：** 解锁"人格特质趋势图"——用户第一次看到自己3天的矛盾演变
- **连续5天：** 解锁"成长方向预测"——AI基于5天数据预测你下一步可能的成长
- **连续7天：** 解锁"你是谁"总结页——一周人格画像，可分享到朋友圈

**断签惩罚（温柔版）：** 不是扣分，而是告诉用户——"你中断了，之前的洞察会暂时变得不完整。再写3天就能恢复完整度。"

### 2.3 社交裂变钩子

**洞察草稿的终极增长武器：让用户的自我认知变成社交货币。**

- **可分享的"人格快照"：** 生成一张精美的图片，包含用户本周的洞察摘要（脱敏后）
- **"看看AI怎么说你"：** 用户把截图发朋友圈，朋友好奇→下载→注册→写第一篇→飞轮启动
- **里程碑海报：** "我已连续写日记30天，AI说我是一个正在从迷茫走向清晰的人"

## 三、洞察草稿的数据架构（面向留存优化）

### 3.1 必须追踪的留存指标

```typescript
interface InsightDraftMetrics {
  // 核心留存指标
  daysWritten: number;           // 累计写作天数
  currentStreak: number;         // 当前连续天数
  longestStreak: number;         // 最长连续天数
  insightCompleteness: number;   // 洞察完整度 0-100%
  
  // 增长指标
  insightVersion: number;        // 洞察版本号（每次更新+1）
  lastWowMoment: string;         // 最近一次"Wow"时刻
  nextMilestone: Milestone;      // 下一个里程碑
  shareableInsightReady: boolean;// 是否有可分享的洞察
}

interface Milestone {
  type: 'streak' | 'version' | 'depth';
  threshold: number;
  reward: string;           // 解锁什么
  currentProgress: number;  // 当前进度
}
```

### 3.2 洞察草稿的"版本号"设计

**这是最关键的留存机制：让洞察草稿变成一个"养成系统"。**

```typescript
interface InsightDraft {
  id: string;
  userId: string;
  version: number;          // 每次更新+1，用户可看到"你的洞察已更新到V12"
  
  // 四维洞察
  todayTheme: InsightField;      // 今日主线
  coreContradiction: InsightField; // 核心矛盾
  personalityTrait: InsightField;  // 人格特质
  growthDirection: InsightField;   // 成长方向
  
  // 留存引擎字段
  completeness: number;     // 完整度百分比
  nextUnlock: string;       // "再写2天解锁成长预测"
  wowSummary: string;       // 一句话钩子，用于push通知
}

interface InsightField {
  current: string;          // 当前值
  history: string[];        // 历史值（让用户看到变化）
  confidence: number;       // AI对这个洞察的置信度 0-100%
  firstSeen: string;        // 首次出现时间
  lastUpdated: string;      // 最后更新时间
}
```

**关键：每个洞察字段都有 `history` 和 `confidence`。**

- `history` 让用户看到"你的核心矛盾从A变成了B"——这是最强的留存信号
- `confidence` 从低到高增长——用户会想"我要继续写，让AI更确定地理解我"

## 五、Push通知策略（用洞察草稿驱动回访）

### 5.1 分层Push策略

| 用户状态 | Push时机 | Push内容 | 预期效果 |
|---|---|---|---|
| 连续写作中（3天+） | 晚上8点 | "你的洞察已更新到V8，今日主线变了" | 当天回访 |
| 断签1天 | 次日中午 | "你中断了，洞察完整度从72%降到65%。写一篇就能恢复" | 次日召回 |
| 断签3天 | 第3天 | "你的洞察已经3天没更新了，AI还在等你回来" | 召回 |
| 里程碑将至 | 达到阈值时 | "再写1篇，你就能解锁'一周人格画像'" | 即时激励 |

### 5.2 Push的"钩子"设计

**绝对不能发"别忘了写日记"这种废话。每条Push必须包含一个"信息差"：**

```
❌ "今天还没写日记哦~"
✅ "你的核心矛盾今天可能有变化——写一篇验证一下？"

❌ "连续写作3天了，加油！"
✅ "你的洞察已更新到V3。想知道AI今天怎么理解你吗？"

❌ "好久没写日记了，回来看看吧"
✅ "你的洞察完整度停在了58%。只需要3篇，就能解锁'你是谁'总结"
```

## 六、成本控制（MrBeast 的ROI思维）

### 6.1 每次更新的真实成本

```
增量更新prompt（input）：~800 tokens = ¥0.008
AI生成新洞察（output）：~300 tokens = ¥0.006
总计：每次更新 ¥0.014

一个活跃用户每天写1篇 = 每月 ¥0.42
```

### 6.2 优化方案

| 策略 | 节省 | 用户感知 |
|---|---|---|
| 本地缓存最近一次完整洞察，只发增量 | -30% input | 无感知 |
| 置信度>90%的维度不再更新 | -20% output | "你的主线已确认" |
| 连续3天无变化时降频到每3天更新一次 | -50% 调用 | "洞察已稳定，等待新突破" |

> **"洞察草稿系统做得再精妙，如果用户写完第一篇日记后，花了3秒才看到洞察——他永远不会写第二篇。你的竞争对手不是其他日记App，是抖音的下一条视频。你有3秒。"**
