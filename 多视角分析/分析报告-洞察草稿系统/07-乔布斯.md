# 洞察草稿系统设计：极致简约

*——Steve Jobs 视角*

---

## 一、先问一个刺痛的问题

你们在问"草稿该存什么字段"。

我问的是：**这个产品，用户打开它的时候，期待感受到什么？**

答案不是一个数据结构。答案是：**"啊，原来我在变。"**

那一瞬间的震颤。不是今日主线，不是核心矛盾，不是人格特质，不是成长方向。

那是四个字段。用户不需要四个字段。用户需要**一个真相**。

---

## 二、删掉一切可以删的

我做第一代 iPhone 的时候，团队拿来的原型有 47 个物理按键。我说：一个。最后我们连那个都去掉了——home 锁在屏幕里。

你们现在设计的洞察草稿是这样的：

```
{
  "今日主线": "...",
  "核心矛盾": "...",
  "人格特质": "...",
  "成长方向": "..."
}
```

**四个字段，全部删掉。**

为什么？因为这四个字段是**分析师的视角**，不是**用户的视角**。用户不关心"核心矛盾"这个术语。用户关心的是：

> "你最近好像一直在纠结同一件事，但你处理它的方式，和三个月前不一样了。"

**这一句话，比四个字段更有力量。**

所以我的设计只有一个字段：

### 存储结构：一个句子

```typescript
interface InsightDraft {
  userId: string;
  sentence: string;      // 一句话洞察
  updatedAt: Date;       // 最后更新时间
}
```

就这样。**一个 `userId`，一个 `sentence`，一个时间戳。**

三个字段。比你们的四个字段还少一个。但力量大十倍。

---

## 三、为什么是一句话？

因为**记忆是一句话的长度**。

你回忆一个人，脑子里浮现的不是一张表格，是一个画面、一句话、一个瞬间。

- "你是个总在别人需要你时出现的人。"
- "你最近开始说'不'了，而且没有内疚。"
- "你已经很久没提那个让你焦虑的事了。"

用户看到这样的句子，**心跳会加速**。这就是洞察。

"今日主线"是报告。"核心矛盾"是分析。"人格特质"是标签。**一句话是真相。**

真相不需要四个字段。

---

## 四、增量更新：不是合并，是演化

你们在纠结"增量更新 prompt"——新日记来了，怎么和旧草稿合并？

我的答案：**不要合并。覆盖。**

为什么？因为人是会变的。上个月的洞察可能是错的。如果旧洞察还留着，它会**污染**新洞察。

每一次更新，就是让 AI 重新看最近 N 条日记，重新生成一句话。旧的那句话，扔掉。

```typescript
// 更新逻辑：极其简单
async function updateInsight(userId: string): Promise<string> {
  const recentEntries = await getRecentEntries(userId, 7); // 最近7天
  const oldInsight = await getInsight(userId);
  
  const prompt = `
    你是用户最亲密的朋友。
    这是ta最近写的东西：${recentEntries.map(e => e.content).join('\n---\n')}
    
    ${oldInsight ? `上一次你对ta的印象是："${oldInsight.sentence}"` : ''}
    
    用一句话，说出你现在对ta最深的印象。
    不要分析，不要标签，不要术语。
    就像朋友聊天时随口说出的那种。
    只输出这一句话。不要解释。
  `;
  
  const sentence = await callAI(prompt);
  await saveInsight(userId, sentence);
  return sentence;
}
```

**覆盖，不合并。** 就像你不会把上一版简历和这一版简历"合并"。你写新的。

## 五、注入回声：不是"加上去"，是"融为一体"

你们在问"草稿怎么注入回声 prompt"。

不要把草稿当成一个"附加模块"注入。**让草稿成为回声的灵魂。**

回声 prompt 不是这样的：
```
先生成一个回声，然后参考一下洞察草稿。
```

回声 prompt 应该是这样的：
```
你对这个人的了解是："ta最近开始学会拒绝别人了，但还有点不习惯。"

ta今天又写了一篇日记。

用你对ta的了解，回应ta今天的日记。
不要提你知道的那句话。让它自然地流露出来。
就像一个老朋友——不会说"我记得你上次说……"，而是带着对你的理解，说出此刻该说的话。
```

洞察草稿不是回声的"参考"，是回声的**潜台词**。

---

## 六、冷启动：第一天就要有东西

新用户第一天写日记，没有历史数据，怎么办？

**不要什么都不给。**

```
// 第一天的洞察，不需要 AI，用一个通用句子
const defaultInsight = "你刚刚迈出了第一步。这本身就是一种勇气。";
```

第二天，就有了两篇日记，足够生成第一句真正的洞察。

**第一天的体验，决定了用户是否回来。** 不能让第一天是空白。

---

## 七、成本：你们想太多了

你们在担心 API 调用成本。

我的回答：**如果产品让人离不开，成本不是问题。**

但实际上，这个设计的成本已经很低了：
- 一天更新一次洞察 → 一天一次 API 调用
- 只生成一句话 → token 数极低
- 注入回声 → 已有的回声调用，不额外增加

你们花在"成本优化"上的时间，不如花在**让那句话更准**。

---

## 八、前端：怎么展示这一句话

不要做成一个"洞察面板"。不要做成一个"数据看板"。

**一句话，只需要一个角落。**

在日记本的右下角，或者回声的开头，用一种比正文小一号的、灰色的、斜体的文字，静静显示：

> *你最近开始说"不"了，而且没有内疚。*

不用按钮。不用展开。不用管理。**它就在那里，像一个朋友的低语。**

每次更新，它悄悄变化。用户某天突然发现——"这句话变了"。

**那一刻，就是魔法。**

---

## 九、最终设计总结

| 维度 | 设计 |
|------|------|
| 存储 | 3 个字段：userId, sentence, updatedAt |
| 更新策略 | 每天一次，覆盖式，看最近 7 天日记 |
| 注入方式 | 作为回声的潜台词，不是附加模块 |
| 冷启动 | 默认一句话："你刚刚迈出了第一步。" |
| 展示方式 | 斜体灰色小字，安静地待在角落 |
| 成本 | 一天一次 API 调用，几乎为零 |

## 十、最刺耳的一句话

**你们设计了一个有四个抽屉的柜子，每个抽屉写着"今日主线""核心矛盾""人格特质""成长方向"——然后争论每个抽屉该放什么东西。**

**但用户根本不想打开柜子。**

**用户想要的，是你走到ta面前，看着ta的眼睛，说出一句让ta愣住的话。**

**那句话，就是整个洞察草稿系统存在的全部理由。其他的一切，都是噪音。**
